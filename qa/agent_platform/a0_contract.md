# A0 integration contract (2026-09-30)

For A1 and the coordinating agent. This is an integration note, not acceptance status.

Required persisted AgentRun facts: owner, conversation, nullable work/requirement, root_run/parent, runtime_thread_id/runtime_run_id, state, operation_key, authorization/session snapshot, fence, deadline, policy_snapshot and counters. Root admission must serialize changes to the same root; native update/resume cannot reset it. Counters cover physical model attempts, all tool calls, child creation and domain creation. Active reservations and elapsed time remain durable on unknown outcomes. AgentEvent.event_key must be unique for native completion deduplication. A0 will adapt to A1's final field names without modifying its files.

Model adapter requires one authenticated gateway request for each physical attempt, with no hidden automatic retry. Expected gateway protocol is structured messages/tools/tool_choice with assistant tool_calls, actual model identity, optional usage and duration; endpoint and exact schema belong to coordinating agent. No provider secrets in graph state.

Production native Runtime license/beacon authorization is not established. Final tests use only synthetic inputs in `.runtime/agent-platform-sdk-venv`; production services and their `.venv` remain untouched. A0 does not authorize real-data entry until AG-15/16 evidence is complete.

Native ancestor messaging was rejected by Codex app tool and no native messaging tool is exposed to this A0 session. This file is the early contract handoff.

## Callable integration (latest)

- `initialize_root(root_id, owner_id)` validates a pre-existing finite policy/deadline and binds identity and installed-skill digest once. Required policy keys: `max_actions`, `max_model_calls`, `max_tool_calls`, `max_launches`, `max_concurrent`, `max_active_ms`. Do not reset existing policy. `policy.identity/fence/active/active_ms/notifications/dispatches` are runtime-owned durable safety facts.
- `NativeRuntime(RuntimeGuard(binding), client, {"researcher", "reviewer"})`: `await start(message, operation_key, graph_id="main")`, `await resume(message, operation_key)`, `await recover_dispatches()`, `await reconcile()`. Child `launch/check/update/cancel/list` remain scoped to the bound root. Unknown dispatch without a discoverable native run stays unknown; it is never resent blindly.
- Native client headers: Authorization bearer `settings.AGENT_RUNTIME_SERVICE_TOKEN` (40+ characters), `X-Agent-Binding: binding.token()`. `get_client(url=..., api_key=None, headers=...)` verified against SDK 0.4.5. Default `get_client(url=None)` uses `/noauth` internally and is deliberately NOT used. `same_deployment_client` constructs the public SDK client with authenticated HTTPX ASGI transport, without that bypass.
- `langgraph.json` registers `main`, `researcher`, `reviewer`; factories bind signed server context and reject mismatching native thread or role. Settings: `AGENT_PLATFORM_ENABLED`, `AGENT_RUNTIME_SERVICE_TOKEN`, `AGENT_RUNTIME_MODEL_PRESETS={graph_id: {"route_code": ..., "selection": pinned_selection}}`, optionally nested by the authenticated user's department. Default presets remain empty. `DJANGO_SETTINGS_MODULE=config.settings` is registered; native auth/lifespan initializes Django, and local commands must set repository/backend PYTHONPATH.
- A2's actual `tools_for_run(guard, message_id=...)` is integrated. `message:<UUID>` operations validate an owned saved user message/content before dispatch and propagate `message_id/operation_key` through trusted Runtime context, checked against the durable intent. Model-visible business tools are hidden before work creation (except `begin_work` and manager read-only tools); after `begin_work` the same graph exposes the authorized business tools without resetting counters. Children never expose `begin_work`. Domain/worker operations must use the same guard for physical model requests and domain admission; A0 does not edit A2 files.
- `gateway_transport(user, route_code, selection, guard)` now persists A1 ModelCallLog `root/run/conversation/work/requirement/physical_call_id` before the actual gateway request. Gateway endpoint is `/v1/generate-agent`.
- Native auth denies all Store HTTP APIs and non-allowlisted resources; backend-internal virtual Store operations use guarded native StoreBackend. Thread/run APIs require both signed binding and current ownership filter. Studio bypass disabled. Revoked/stopped scope may only issue scoped cancellation, not read native run kwargs or checkpoint content.
- Same-deployment lifespan performs bounded non-LLM reconciliation every two seconds, at most 32 roots per pass, with an optional scoped `POST /agent/reconcile`. Execution remains native `runs.create`, not an application graph loop or execution queue. Notification admission/intent is atomic; native metadata recovery and consumed notices prevent duplicate native wakeups. Stop cleanup acknowledgments are persisted without resetting counters.
- Admission requires a committed outer boundary: do not call `admit` inside a database transaction. Use `transaction.on_commit` for dispatch. Admission, child mapping and full historical operation intent commit atomically; exhausted limits persist before the exception. Nested admission is rejected before any action rather than pretending to survive an enclosing rollback. Old message replay returns its exact historic native ID, never the newest run. Same operation with different content is rejected. Unknown sends recover by bounded `runs.list(thread_id, limit=100, offset=...)` metadata matching and are never blindly retried.

SDK validation uses `.runtime/agent-platform-sdk-venv` and locked dependency group `agent-runtime`. UV downloads timed out; exporting the same lock and installing with pip succeeded, followed by `pip check`. Earlier isolated experiments used `qa/agent_platform/.venv`; project `.venv` was never synchronized or changed.
