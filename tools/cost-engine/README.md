# 工程成本测算引擎与定额库

本目录是平台「工程成本」能力的外部测算程序，以及陕西省定额库。

## 目录内容

| 文件 | 用途 |
| --- | --- |
| `cost_cli.py` | **引擎本体**，实现平台约定的三个子命令：`inspect` / `run` / `quota-candidates` |
| `six_set.py` | 「成本测算六件套」输出格式（设备清单／劳务清单／成本测算×2／劳务报价×2） |
| `quota-library.json` | **陕西省定额库：29,316 条**，仅含编号/名称/单位/专业/工序，**不含价格** |
| `build_quota_library.py` | 从基价表 Word 文档重建定额库（见下） |
| `batch_match_quota.py` | 批量套定额：清单逐条比对定额库，输出分级报告与 xlsx |
| `make_list.py` | 生成演示用工程清单 xlsx（列结构对齐平台契约） |
| `samples/` | 演示清单样张（弱电工程 6 条、给排水 5 条） |
| `output/` | 运行产物（不入版本控制） |

## 两类数据的性质完全不同

**请注意区分**，这决定了结果能不能用：

| | 成本测算（`run`） | 定额检索（`quota-candidates`） |
| --- | --- | --- |
| 数据来源 | 按条目名称与地区系数**程序生成**的示范值 | **真实数据**：《陕西省建设工程基价表（2025）》 |
| 用途 | 验证流程与界面 | 人工筛选定额条目 |
| 能否用于投标/结算 | **绝对不可** | 需人工确认，且价格另定 |

`run` 产出的金额**不对应任何真实市场价**。产出文件在标题、列名、警示行、数据来源列均已标注「演示」。

## 定额库（真实数据）

来源：省住建厅公开的《陕西省建设工程基价表（2025）》Word 转换稿（7 册、8170 页）。

| 专业 | 条目数 |
| --- | --- |
| 通用安装工程 | 14,990 |
| 市政工程 | 6,105 |
| 城市地下综合管廊工程 | 3,912 |
| 房屋建筑与装饰工程 | 2,769 |
| 园林绿化工程 | 1,078 |
| 绿色建筑工程 | 462 |
| **合计** | **29,316** |

### ⚠️ 为什么不输出价格

基价表中**含**价格（基价／人工费／材料费／机具费／管理费／利润），但本工具
**刻意只返回编号、名称、单位、专业**。原因：

**D-05 尚未签认** —— 工程专业、陕西适用定额版本与授权、价格基准日、费用税费口径、
工具版本均未确认。平台规范明确要求「阻断并列出缺口，禁止 AI 猜测」。

定额数据的使用需要授权，价格基准日也需确认。在这些落地之前，工具的职责是
**帮人找到条目**，价格由造价负责人定。这是合规边界，不是功能缺失。

### 检索规则

清单条目的写法与定额条目不同，需要归一化才能比对：

```
清单：电力电缆 YJV-4×25+1×16      ← 带型号
定额：配电电缆敷设工程 铜芯电力电缆敷设 电缆截面(mm²) ≤35   ← 是工序名
```

| 规则 | 原因 |
| --- | --- |
| 剥离型号、尺寸，取中文主干词 | 型号会把字命中率稀释到 0.1 上下，结果不可用 |
| 数字不参与模糊匹配 | 数字是「巧合命中」重灾区（型号／尺寸／管径都含数字） |
| 同一工序章节最多保留 2 条 | 否则查「电力电缆」会返回 5 个不同截面，看不到候选全貌 |
| 单位按归一化结果判定兼容 | 定额惯用扩大基数（`10m`／`100m²`），清单多用基本单位（`m`／`m²`） |
| 分数低于 0.30 不返回 | 宁可少给，也不给明显无关的条目 |

排序：分数 → 查询词在名称中出现次数（越专指越靠前）→ 编号升序。

## 用法

### 1. 平台调用（推荐）

平台通过 `.runtime/local.env` 中的两个变量挂接本引擎：

```ini
PORTAL_ENGINEERING_PYTHON=<python 解释器绝对路径>
PORTAL_ENGINEERING_COST_CLI=<本目录>/cost_cli.py
```

改完需重启 Web 服务与 Worker。平台的 `engineering_worker` 会按契约调用
`cost_cli.py` 的三个子命令。

### 2. 独立运行

```bash
cd <仓库根目录>

# 批量套定额（默认读本目录 samples/）
./.venv/Scripts/python.exe tools/cost-engine/batch_match_quota.py

# 指定清单目录
./.venv/Scripts/python.exe tools/cost-engine/batch_match_quota.py --dir <清单目录>

# 直接检索定额
./.venv/Scripts/python.exe tools/cost-engine/cost_cli.py quota-candidates --name 配电箱 --unit 台
```

### 3. 重建定额库（仅在有源文档时）

`quota-library.json` 已随仓库提供，**通常不需要重建**。
如需用更新版本的定额文档重建：

```bash
QUOTA_SOURCE_DIR=<含「P020250321392712718605」的目录> \
  ./.venv/Scripts/python.exe tools/cost-engine/build_quota_library.py
```

源目录需包含 `P020250321392712718605/各专业工程基价表/*.docx`。
退出码非 0 表示未找到文档 —— 此时**不会**覆盖已有的 `quota-library.json`
（避免把 29316 条数据写成空文件）。

### 提取实现的关键点：工序名在表格之外

基价表表格的「项目名称」列只写规格，工序名是**表格前面紧邻的段落标题**：

```
四、电力电缆敷设                  ← 章（表格外）
1.直埋式电力电缆敷设               ← 节 = 真正的工序名（表格外）
┌──────────────────────────────────────────┐
│ 4-9-140 | 电缆截面(mm²) ≤10 | 10m | …      │  ← 表格里只有规格
└──────────────────────────────────────────┘
```

因此必须按文档顺序遍历段落与表格、跟踪章节标题，把工序名并入条目名称。
只遍历表格会丢掉工序名（实测导致近 20% 的条目只剩规格，搜「电力电缆敷设」命中 0 条）。

## 平台契约（本引擎遵循）

| 子命令 | 作用 | 输出 |
| --- | --- | --- |
| `inspect <paths...>` | 预检清单，返回可解析条目数与问题 | JSON |
| `run <paths...> --region <地区> --output-dir <目录>` | 生成成本草稿 | JSON + xlsx |
| `quota-candidates --name <名称> [--unit <单位>]` | 检索定额候选 | JSON |

约束：

1. 退出码：0 成功，非 0 失败（失败时输出 `{"ok":false,"code":...}`）
2. 路径沙箱：只读写 `--output-dir` 内的文件
3. 双层 SHA256：`input_sha256`（各输入文件哈希）与 `output_sha256`（产出文件哈希），
   平台下载前会校验，被改过即拒绝
4. **`quota-candidates` 不得输出 `price` 字段** —— 平台遇 `price` 判定能力不可用
5. 候选字段为**固定白名单**：`code` / `major` / `name` / `unit` / `score` /
   `original_source` / `unit_compatible`。**不得新增字段**，否则平台校验失败

## 换成你们真实的测算程序

`run` 目前由本演示引擎提供（金额为示范值）。如果公司已有成本测算程序：

- **符合上述契约** → 改 `local.env` 的 `PORTAL_ENGINEERING_COST_CLI` 指向它，重启即可
- **接口不同** → 写一层适配器把它包成符合契约的形式

定额检索部分（`quota-candidates`）是真实实现，无需替换。
