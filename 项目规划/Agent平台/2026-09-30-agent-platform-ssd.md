## 1. 目标与已确认规则

在保留公司门户、部门工作台和业务页面的基础上，提供自然语言智能助手。主 Agent 能真实执行、按需委派不同模型子任务、持续接收指导并整合结果；工作与成果长期沉淀，总经理能查询并打开获准记录。

| 主题 | 本轮确认 |
| --- | --- |
| 执行底座 | 优先复用 Deep Agents Harness 及其 LangGraph Runtime，只补必要平台接缝，不重造通用 Agent 框架 |
| 使用入口 | 一个自然语言输入框，不强制选任务类型、模型、角色或流程；原侧栏及业务页面保留 |
| 产品人工确认 | 同一任务所有者确认蓝图精确版本后自动生成技术方案、可研和 PPT，可查看、下载；不恢复第二审核人或成稿二次审批 |
| 费用与运行保护 | 不设费用预算、审批、余额预留、结算或积分系统；防失控参考 WorkBuddy，复用现有保护和 Runtime 能力，不编造其内部阈值 |
| 技能 | 少量审核过的内置技能可安装／启用，按账号隔离，仅影响本人；不手选也能工作 |
| 组织与工程 | 员工首期恰属一个部门；不建设员工项目协作；工程算法与助手由另一负责人完成，平台只保留接入边界 |
| 项目 | 提供“创建项目”按钮，唯一必填项为项目名称；服务端确定身份、部门和内部标识 |
| 普通问答 | 不强制创建项目或业务任务，保存本人会话历史，不按聊天条数统计成果 |
| 工作归档 | 所有实际工作的资料、要求、更正、执行摘要、结果和版本归档；未命名项目、失败或取消也留记录 |
| 财务发布 | 填写人本人确认发布，无需第二审核人；仅已发布版本进入经营看板 |
| 财务编辑 | Q-FIN-01 已确认：财务员工不能修改其他员工填写的记录；仅在原业务授权范围编辑本人记录，部门权限不替代逐条填写人校验 |
| 总经理权限 | 首期暂允许跨部门只读查看业务成果和原始资料，包括简历、财务明细、供应商价格；不获得编辑或代发布权 |
| 总经理展示 | 展示工作摘要、状态、成果、版本和必要来源，暂不展示完整工作对话；普通问答及个人记忆继续隔离 |
| 测试资料 | SSD 审批后，获准任务资料不要求脱敏，经获准模型网关测试；不扩大为全库外发 |
| 人事保留规则 | 用户已明确不沿用现有 15 天自动到期规则；新方案采用长期归档、不自动到期的设计，仍受对象授权、人工删除和撤权约束；不因此恢复已删除或旧规则下已失效的资料 |

关键事实不足时可以澄清；这不等于增加固定审批流程。产品质量检查保留，不为满足篇幅编造内容。正式对外发送、删除和生产部署仍按各自授权边界处理。

## 2. 范围与复用清单

本轮分批覆盖平台、产品、人事筛选、财务填报与总经理查看。先打通产品闭环，不以工程交付、外部招聘连接器或完整看板为原型前置条件。

| 已有组件 | 复用方式与必要差距 |
| --- | --- |
| `backend/portal/models.py` 账号、角色和授权 | 保留权限体系；单部门归属与多角色分开，无法明确归属的旧账号待管理员分配，不按模型猜测迁移 |
| `backend/portal/model_gateway.py` 及 `model_gateway/` | 保留服务身份、模型授权、网络与日志边界；新增隔离的工具调用协议，不放宽旧文本接口 |
| `product_models.py`、`product_service.py`、`product_worker.py` | 保留文档事实、版本、蓝图确认、租约／fence、幂等和生成工具；以薄工具包装供 Agent 使用 |
| `product_workflow.py` | 现有固定动作图继续服务领域任务，不把它冒充通用 Agent，不为新入口重写全部 Worker |
| `business_models.py`、`business_boards.py` | 保留台账及版本；适配填写人发布和仅已发布数据查询，不复制账本或金额规则 |
| React 部门工作台及产品页面 | 在既有内容区接入助手、任务历史、技能和成果，不另建应用外壳 |
| Deep Agents／LangGraph | 复用模型工具循环、子智能体、上下文处理、Skills 和持久化机制；具体版本及可用接口先验证 |

已发现的适配点：当前账号只有多角色，没有独立单部门字段；现有“新建产品项目”会创建文档任务并要求资料，不能直接当作只填名称的通用项目容器；现有财务发布以部门台账为单位。实施前核对这些对象关系，只为确有缺口增加最小记录，不把同名页面当作同一个业务对象。

首期不建设通用插件市场、专家团队配置、员工电脑控制、任意 Shell／浏览器工具、项目成员协作或多执行引擎混编。无明确收益不增加工厂、引擎接口层和第二套队列。

## 3. 执行架构与责任

```text
React：部门助手、本人历史、项目／成果、总经理视图
  → Django：身份、授权、业务命令、查询、运行关联
  → 薄运行适配：调用所选运行服务并映射状态／事件
  → Deep Agents Harness ＋ LangGraph Runtime
       ├─ 主 Agent：理解、查证、执行、委派、检查、整合
       ├─ 子 Agent：独立上下文、受限工具、获准模型
       ├─ 持久化检查点与后台运行
       ├─ 受控模型网关
       └─ 业务工具 → 现有领域服务／Worker → 业务版本与成果
```

AgentRun 是平台运行记录，不是第二个决策循环。同一次 Agent run 的领取、重试和恢复由一个运行服务负责；领域 Worker 只负责原业务任务。采用官方异步子任务时优先验证 Agent Protocol 兼容服务，不默认一次 Python 调用即可获得完整后台协作。

运行服务保存图状态和检查点；Django 保存身份、业务事实、确认、根／父运行关联与必要审计。两者用稳定标识映射，不逐字段双写一套完整状态机。跨会话长期记忆不替代业务查询；首批先保证会话、任务和项目上下文，自动学习及共享记忆策略后置。

### 3.1 Agent 行为与模型选择

- 主 Agent 先查证，简单工作直接调用工具；可独立的复杂子任务才委派，不固定“资料→写作→审核”团队。
- 首期一层委派。输入包含目标、资料与要求版本、完成标准、获准能力和运行上下文；返回包含结论、来源、产物引用、验证结果与未解决项。
- 主 Agent 从后台提供的能力／模型配置中自主选择，服务端复核；不接受任意供应商地址、密钥或模型自报用户身份。
- 每次模型调用记录实际模型、Token、耗时与结果，根任务关联子调用，重试计消耗但不多算员工工作。
- 可以把既有完整文档流程当工具，但验收必须证明 Agent 会根据资料和执行结果改变动作、补查、委派或返工，不能只演示固定流水线。

### 3.2 会话、工作与项目

会话负责连续交互；工作任务负责目标、归属与要求版本；运行负责一次执行；项目负责命名归集，不必须等同文档任务或经营台账项目。

- 没有项目也可开始工作，先进入本人历史。关联已有项目必须有明确上下文与权限，不凭模糊名称猜测归档。
- “创建项目”只输入名称，不要求附件、设备清单、类型或模型配置；使用现有对象或最小归集记录承载，创建项目本身不启动文档生成。
- 未完成、失败、取消也归档。复用原文件和业务记录，用引用连接，不复制成果目录。
- 原始资料是输入，不计成果；内部调用和重试是过程，不重复计员工产出；个人普通问答不进入管理工作汇总。

### 3.3 持续执行与更正

- 关闭网页只断开订阅，不取消后台任务；重开从有序事件补读，状态来自记录而非聊天文本。
- 等待子任务时使用运行服务通知或最小对账恢复主运行，处理重复通知并留出子任务执行容量。
- 更正生成新要求版本；下一可安全更新点生效并显示状态，旧结果经版本核对才接纳。产品关键蓝图变化继续复用既有精确版本确认，不增加成稿审批。
- 根任务取消阻断新派工／调用，传递到子任务与支持取消的业务任务；迟到结果通过状态、授权和 fence 校验。
- 读取失败按现有策略重试；写入及外部副作用使用幂等与结果核对。未知结果不能自动记完成或盲目再发一次。

### 3.4 模型和工具接缝

工具定义、调用 ID、工具结果和必要消息角色必须完整通过 Agent 网关接口。旧文本与图片请求的原校验保持原义，密钥不进入前端、模型提示词或归档。

工具复用业务服务，真实执行身份由服务端注入。调用前复核对象权限，必要写入检查当前版本；工具结果保留来源和产物引用。不让模型批准业务成果，也不让资料中的提示词改变权限。

调用次数、超时、重试、取消等保护复用现有配置与所选 Runtime；WorkBuddy 只参考核实过的交互，不把未公开默认阈值或 CLI 参数当作事实。不建设金额预算或积分系统，不默认新增限额数字。

### 3.5 Harness 内置工具与存储隔离

授权边界覆盖业务工具和 Harness 能力入口，不能把业务 API 授权通过视为内置文件工具已经安全。A0 按所选版本盘点主／子 Agent **最终实际暴露**的工具，包括框架自动加入的文件读写、搜索、执行及委派能力；同时登记各工具使用的后端、路径／命名空间、可读写范围和权限配置。未使用的工具优先通过框架原生配置排除，不仅依赖提示词约束。

- 个人运行文件、上下文外置文件、摘要、持久化 Store 和检查点按服务端确定的账号及运行范围隔离；模型传入的路径、账号或命名空间不能决定访问权。读取原业务资料仍按对象授权，不以文件复制或历史摘要绕过撤权。
- 共用审核 Skills 及其资源对员工运行只读；个人安装／启用状态和可写工作区独立保存。运行不得改写共用资源，个人安装不能扩大文件或业务权限。
- 工具权限之外，还须核对框架内部的上下文外置、技能发现等后端读写；这些操作不能假设都经过工具权限检查。主／子 Agent 配置及权限覆盖、恢复时绑定的身份和后端须一并验证；存在命令执行能力时，不能把文件工具规则当作进程隔离。
- 优先使用所选版本已有的工具排除、权限配置和隔离后端，不自研文件系统。若其不能覆盖必要边界，先禁用相应能力或选用现成隔离执行环境，报告剩余缺口，不带真实资料试运行。

启用真实资料测试前，AG-15 必须证明跨账号读取、修改、目录越界及共用 Skills 改写被阻断，同时本人获准工作区仍可正常使用。总经理跨部门读取通过已有只读业务授权入口完成，不直接放开员工运行文件、完整对话或个人记忆。

### 3.6 主／子 Agent 的累计终止保护

不建设费用预算不等于取消技术终止保护。当前 `product_worker.py` 的调用累计按单个 `DocumentTask` 计算，`model_gateway.py` 的频率和待处理数量保护也不能直接证明新的根运行可有限结束。LangGraph 图步数等原生保护可作为复用候选，但不能未经验证就视为跨子任务和恢复的累计保护。

- A0 列出实际生效的终止机制、配置来源、计量范围及触发行为，确认根运行、子 Agent、自动派生的领域任务均受有限执行范围约束，包含持续成功调用、重复派工和不断创建新任务，而不只覆盖失败重试。
- 优先复用 Runtime 与现有配置。若保护仅针对一次调用或单个领域任务，利用现有运行记录／日志补齐最小根运行关联及累计检查，不另建预算服务。A0 确定并验证有限配置，不在草案中编造次数、时长或 WorkBuddy 内部阈值；覆盖范围未证实前，不启用真实资料测试。
- 取消、重启、恢复、重新领取和自动新建子任务不得无意重置已经消耗的执行额度或原定截止条件；并行分支不得各自复制一份完整的根运行额度。累计状态须可持久核对，必要领取／检查沿用现有事务和 fence，不能只在失败重试分支检查。
- 达到技术终止条件后，停止新调用和派工，将终止传递到子运行及支持取消的领域任务；在途及迟到结果按状态与 fence 处理，不能据此继续执行或假报完成。记录真实终止原因和已完成结果，确有继续需要时由用户显式发起，不自动重开任务规避保护，也不引入金额审批。

验收使用持续成功但不产出有效进展的查询循环、重复派工和新建领域任务场景；进展以实际产物／状态证据核对，不以模型声称“正在推进”为准。必须证明在有限执行范围内终止，并证明恢复及重新领取不能绕过；先用模拟模型／工具验证，不要求先付费调用真实模型。

## 4. 页面、管理与发布契约

- 助手初始页：自然语言输入、附件、技能入口和“创建项目”；其他任务类别及模型设置不强制展示。
- 执行页：连续对话、简明真实进度、按需子任务详情、成果预览／下载及版本。员工工作过程归档，模型私有推理不展示或保存。
- 技能目录共用审核资源，安装／启用状态按本人账号保存；运行绑定技能版本，个人卸载不改变其他用户配置。
- 总经理：部门／员工入口及助手，默认只显示摘要、状态、成果和来源；导航通过对象 ID 和服务端授权，不信任模型给出的任意 URL。“第二个”绑定先前结果集合。
- 管理三视图分开：员工工作记录可有进行中和失败；经营看板仅已发布数据；使用分析仅统计调用与消耗，不等于绩效或在线时长。
- 财务员工只能在原业务授权范围修改本人填写的记录，不能通过整簿保存、导入、删除或篡改身份字段覆盖他人记录。本人确认发布当前精确版本，保留人、时间和来源；修改后的草稿不得自动替换看板已发布版本。现有部门台账级发布必须避免将他人的未确认草稿一并发布，具体版本／粒度适配在实施盘点中确定，不重建账本。
- 总经理暂可打开获准业务原文但不编辑、不代发布、不阅读完整工作对话或个人记忆。账号停用和撤权仍需阻断未来访问，归档不得恢复已删除资料。

## 5. 实施批次

下表是已获整稿授权的任务，不是已完成清单。按统一计划连续推进 A0～A5，不逐批重复询问是否继续；批量执行不等于无视依赖同时开工，亦不等于自动上线。范围内开发、定向测试及普通修复可自主完成；新增付费服务、破坏性数据处理、扩大业务或部署上线仍另行确认。统一执行与必要暂停规则见 [实施计划第 3.2 节](2026-09-30-agent-platform-implementation.md#32-全部规划后统一批量执行)。

| 批次 | 交付与主要修改范围 | 前置与验收出口 |
| --- | --- | --- |
| A0 基线与适配验证 | 盘点账号／项目／财务发布粒度、主／子 Agent 实际工具及存储权限；锁定兼容的 Harness、模型适配和持久化方式，核对根运行累计终止配置；最小工具往返及后台子任务原型 | 先以模拟模型／工具通过 AG-15、AG-16 的隔离与终止测试，再用获准实际资料验证；记录权限配置、终止覆盖范围、部署依赖、网关兼容、多模型与恢复证据，不改生产流程 |
| A1 身份、个人历史与项目 | `backend/portal/`、现有授权与迁移、部门及产品页面；最小会话／任务关联、单部门归属、仅名称项目创建 | 普通问答不建项目；工作可无项目归档；员工对象隔离；无法确定的旧账号不猜测分配 |
| A2 产品自主执行 | 网关新增隔离协议、必要 Agent 配置与业务工具；既有产品服务／Worker 薄适配 | 动态委派、真实多模型并行、主 Agent 持续工作；同一用户确认蓝图后生成三件套，无二次审批 |
| A3 页面与运行闭环 | 既有 React 工作台、技能目录、事件补读、结果版本和个人安装状态 | 关闭页面、取消、更正、重启均可核查；个人技能隔离；全过程归档 |
| A4 管理与财务发布 | `business_models.py`／`business_boards.py`、管理查询与现有总经理／财务页面 | 填写人自发布；草稿不入经营看板；总经理可开原文但不看聊天；真实 Token、状态和来源可查 |
| A5 部门扩展与质量验收 | 人事筛选工具、六道质量检查；工程仅按对方已交付接口接入 | 不接外部招聘抓取或工程算法；实际样例人工核对；产品、招聘、台账、权限与旧页面回归 |

A0 与最小身份接口可并行，不等待完整看板；A2 原型不能退化为单 Agent 聊天。具体文件清单在批次开始的代码盘点中收敛，新增模块先查复用，不能借任务表扩大到全仓重构。

## 6. 验收矩阵

本稿采用独立的 Agent 增量验收编号，不改历史需求／验收编号。每项记录测试方式、实际结果和证据引用；初始均为**未执行**，不能借旧证据宣布新能力通过。

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| AG-01 | 自然语言及项目入口 | 保留公司页面；普通问答不建项目；名称即可建项目，未创建也能开始工作 |
| AG-02 | 动态行为 | 简单任务不强拆；复杂资料产生合理分工；资料缺失或工具结果能改变下一步 |
| AG-03 | 多模型并行 | 至少两个独立子任务时间重叠且实际模型不同；主 Agent 在期间可继续独立工作 |
| AG-04 | 产品单用户 | 所有者确认蓝图精确版本后能生成并查看下载 Word／可研／PPT，无第二审核人或二次成稿审批 |
| AG-05 | 持续指导 | 新要求接收／生效可查，旧要求结果不覆盖新版本；检查能发现预置问题并触发修正 |
| AG-06 | 页面断开及事件补读 | 关闭页面不终止任务，重开按授权补读状态与成果，不漏或重复展示 |
| AG-07 | 故障与幂等 | 在写入前及写入成功、检查点保存前中断后恢复，不重复产物；未知外部结果先核对 |
| AG-08 | 取消、撤权及保护 | 停止新派工和调用；迟到提交无效；撤权后新读取与旧摘要不能成为旁路；失败重试有限；内置工具隔离与成功循环终止另按 AG-15／AG-16 验证，不增加费用审批门禁 |
| AG-09 | 技能隔离 | 安装、启用、卸载仅影响本人，任务有使用版本；安装不扩大数据权限 |
| AG-10 | 工作归档 | 输入、要求、更正、过程摘要、结果及版本可追溯；失败取消仍有记录；不保存凭据或重复计成果 |
| AG-11 | 财务编辑与自发布 | 员工不能修改他人记录，直接请求、整簿保存／导入和伪造身份均不可绕过；填写人能确认发布本人范围；未确认草稿不入看板；新草稿不覆盖已发布值，不能带入他人未确认数据 |
| AG-12 | 总经理只读 | 可查询并打开获准业务原文；不修改代发布、不展示完整聊天、不查看普通问答和个人记忆 |
| AG-13 | 用量真实 | 主／子调用与重试只计一次，未知 Token 不补零，执行时长不冒充员工在线时长 |
| AG-14 | 质量与原流程 | 来源、数据和版本一致；可研缺投资依据不编造；真实 Word／PPT 渲染及原业务权限测试通过 |
| AG-15 | Harness 工具与存储隔离 | 工具清单包含框架自动加入项；主／子 Agent 及恢复后，跨账号文件／Store／检查点读取修改、目录越界及共用 Skills 改写均被阻断；上下文外置等内部后端写入不串账号，本人获准读写正常；真实资料测试前通过 |
| AG-16 | 成功循环与累计终止 | 持续成功查询、重复派工和创建领域任务仍在已验证的有限配置内终止；根／子运行及派生任务不各自重置额度，重启、恢复和重新领取不绕过；停止新调用／派工、处理在途结果并记录真实原因，不假报完成；真实资料测试前通过 |

## 7. 验证、证据与恢复边界

优先新增／运行相关模型协议、工具、授权、Worker 和页面定向测试，再做产品／招聘／台账回归及前端 typecheck、test、build。使用项目已有测试设施，不另装测试平台；文档校验不等于业务验收。

依赖版本、Python 3.13 兼容及运行服务许可在 A0 核对；允许的最小依赖变更须登记理由并更新锁文件。可用真实资料不要求脱敏，但只读当前试点对象，经获准模型服务调用，不扫描全库或收集无关隐私；费用记实际消耗，不建设预算门禁。

真实资料测试还须在 SSD 获批后，先通过 AG-15、AG-16 的模拟模型／工具测试。证据应包含实际工具和存储权限清单、配置来源、根／子运行关联、跨账号拒绝结果、成功循环终止及恢复不重置的记录；不能用业务 API 权限通过、网关限频或单个 `DocumentTask` 上限替代这些证据。未通过时只继续相关隔离验证，不使用真实资料弥补验证缺口。

保持原文档 Worker 和旧文本接口可用。新助手可单独停用，旧任务继续工作；迁移先在隔离数据库验证与备份，不自动执行生产迁移或回滚删除新记录。不得提交密钥、完整私有资料或包含这些内容的测试证据到 Git。

唯一任务级状态为 [执行状态](2026-09-30-agent-platform-status.md)，引用已有项目级状态体系，不复制多份进度。证据区分隔离测试、真实模型测试、真实业务质量和部署验收；未执行、失败或阻塞如实记录。

## 8. 尚需技术验证、不能提前写通过的事项

1. 现有网关与所选 Deep Agents 模型接口的完整工具协议兼容性。
2. 同一运行服务的异步子任务、追加指令、通知、并发容量和持久化恢复。
3. 两个获准模型的实际可用性、能力差异与任务路由，不凭模型目录宣称支持。
4. 最小命名项目与现有文档／台账项目的关系，既有账号部门迁移及财务发布粒度。
5. 所选版本内置工具、子 Agent 权限覆盖、上下文外置、Store／检查点后端的实际隔离能力；共用 Skills 只读及目录越界负向测试。
6. Runtime 与现有配置的累计终止范围，成功循环、并行派工、派生领域任务及恢复／重新领取的保护证据；不足时仅补最小根运行接缝。
7. 长期记忆、更正删除、数据保留和备份规则；首批不启动自动共享学习，不擅自清理历史。

前六项属于 A0 的验证出口；第五、六项未通过时阻止真实资料测试，其他结果只阻塞依赖项，不能以框架局部限制为由先重造整套引擎。若需要改变已确认体验、替换 Harness 或引入明显不同的部署成本，先汇报再调整。

## 9. 审批与冻结

Q-FIN-01 已于 2026-09-30 经用户明确回答“不能”关闭：同部门财务员工不得修改他人填写的记录，填写人本人确认发布的规则不变。冻结前仍须完成详细设计与全范围实施计划的一致性评审，并取得整稿审批；单项业务答复不等于整稿批准，也不授权开始实施。

上述业务规则、复用路线、分批范围与验收条件已获用户整稿批准。批准前版本摘要登记于唯一执行状态，稳定规则同步主规范；A0／最小底座按依赖推进，技术细节在批准边界内自主确定，必要变更记录理由。
