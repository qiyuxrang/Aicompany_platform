# 企业智能体平台：需求对照与运行边界

对应 2026-09-26 的四部门产品需求。本文件记录代码实现、使用约束和升级影响；不将隔离测试等同于生产部署或外部服务联调。

## 功能对照

| 需求 | 实现入口 | 关键行为 |
| --- | --- | --- |
| 统一登录与首次改密 | `/login`、`/password` | 预置账号；首次登录新密码与确认密码双输入；后端校验并保存哈希，旧会话失效；单部门账号直接进入部门 |
| 资料到项目蓝图 | 产品新建项目、项目详情 | 设备清单与背景资料分类、持久任务进度、可核对来源、版本连续性 |
| 修改意见与人工批准 | 项目蓝图 | 意见产生新版本；批准绑定准确版本，继续生成三件套草稿 |

## 数据与判断的边界

新建项目向导采用明确的 `equipment_background` 资料契约：设备清单单独上传且只能有一份，至少一份背景材料才能开始生成。可以先保存不完整草稿，再在资料页按类型补充。旧版手工／专业任务保留原输入契约，不把历史未分类附件强行认作设备清单。

文件在上传时解析；Worker 随后核对和汇总当前资料快照、检查设备事实，再进行蓝图模型生成。这三步分别持久化状态、时间和实际处理数量，不代表三次独立模型调用，也不使用计时器伪造进度。修改意见绑定当前蓝图及审核记录后重新排队，下一次模型输入携带原蓝图与意见；生成完成后仍需人工审核。


产品三件套的**草稿生成、正式渲染、最终发布是不同状态**。真实模型调用许可、模板批准、Office 渲染等条件没有满足时，系统保持明确的等待／失败状态，不把“已排队”写成“已交付”。现有蓝图审核及文件解析仍沿用原有来源、版本和人工核对规则。

简历工具提供辅助审核，不自动作出录用决定。无法核实的要求应显示待补充；年龄信息不进入打分或排除规则。用户应人工检查 JD 提取出的要求、匹配证据与异常项。

总经理 BI 是平台内的**台账快照分析**，不是原企业系统的实时同步。原系统导航、身份映射与只读项目桥接保留，不修改外部接口的授权边界。浏览器单点登录不因此自动实现。

## RAGFlow 对接

原生问答配置使用 `PRODUCT_KNOWLEDGE_*`，与蓝图旧检索配置 `PRODUCT_RETRIEVAL_*` 分开。后者是平台自定义接口契约，不能将两者混称为 RAGFlow 原生接口。

问答调用 `/api/v1/retrieval`，按服务端当前用户授权发送 `dataset_ids` 和 `document_ids`。令牌只在后端环境读取，不接受浏览器传入目标 URL 或任意知识库范围。最多授权 4 个知识库，每库 100 个明确文档；检索与模型上下文均有数量、体积与时间边界。

对话当前最多保留 100 个，每个最多 40 轮；超出会明确提示，不静默丢弃。模型调用失败可以重试，问题使用请求 ID 和会话版本防止重复写入，过期处理不能覆盖新处理结果。授权变化后，旧范围的历史不会继续暴露。

部署需要 HTTPS 的完整检索 URL、URL 白名单、服务端令牌、明确资料授权和绑定产品模块的回答模型路由。服务就绪状态在页面呈现。接口契约参考 RAGFlow 仓库 `docs/references/http_api_reference.md`；适配代码记录了核对版本。合同测试模拟服务响应，不代表本轮已经连接真实 RAGFlow 实例。

## HR 保留期

保留期为创建时间加 15 天，不因更新而延长。招聘需求是对话和 JD 的保留期起点；筛选批次与简历到期时间不能晚于所属需求，也不能晚于批次自身的期限。因此，在某个需求创建第 14 天上传的简历不会再保留完整 15 天。

到期边界包含该时刻：列表、详情、生成、筛选、原件下载和全局旧招聘工作摘要都不能继续返回到期业务内容。自动删除由 HR Worker 在启动及定时维护中执行；独立 `cleanup_hr_history` 命令可用于维护。文件删除失败会报告并保留可重试关联，过期访问仍被拦截。

清理范围包含招聘对话、通用／平台 JD、旧版招聘任务、筛选批次、简历文件与衍生数据，以及过期无引用临时文件。不包含转正档案、员工数据、安全审计、产品项目和台账快照。数据库备份、外部服务日志或已人工下载的文件不由此命令管理，应另行配置保留策略。

## BI 统计口径

每次导入一个部门的完整 UTF-8 CSV，最多 2 MiB、2,000 行。项目编号不可重复；字段、日期、状态和数值必须通过校验，错误文件不会替换当前快照。导入携带上次快照 ID，防止并发覆盖；同内容同日期的重复导入不重复建档。

工程的交付中包括待开工、实施中、待验收、整改中；交付后包括已验收和质保中。只有仍在交付中的项目才可能统计为逾期。

财务统一为人民币元，以十进制定点数计算合同、已收、待收和逾期待收。待收＝合同－已收；不接受已收大于合同的记录。此简化台账不覆盖多币种、退款、分期到期或会计确认流程；需要这些口径时应扩展数据契约，不能直接混填。

售前按线索、需求沟通、方案编制、报价、商务谈判、已赢单、已丢单分组。跟进预计金额不含已赢／丢单，也不乘以未经提供的成交概率。逾期统一按快照截止日期，而非随浏览日期变化。

没有快照的指标为未知（“—”）；已导入快照中某种状态确实没有记录时，数量可以是 0。搜索和状态筛选同时作用于指标、分布与明细，保留完整快照总条数。

## 升级与运行

迁移链在已有产品／HR 合并迁移后继续：

```text
0016_merge_product_intake_hr_recruitment
  → 0017_hr_prd
  → 0018_product_knowledge
  → 0019_business_ledger_snapshots
  → 0020_product_source_purpose
```

迁移本身不执行招聘历史清理。**升级后启动 HR Worker 会开始执行到期清理**，上线前应确认保留期、备份策略和 `PORTAL_HR_STORAGE_ROOT` 指向。不要使用日常数据库运行验收脚本。

Compose 为 HR 文件增加独立持久卷，并启动 HR Worker；产品 Worker 放在 `product` profile，模型网关在 `models` profile。先验证对应环境中的模型、渲染依赖与卷路径，再启用产品任务。当前提交不等于已经启动或重建这些服务。

## 可复现检查

```powershell
# 临时 SQLite、独立文件目录，不读取已有 .env
uv run --frozen python qa/run_prd_tests.py --check-schema
uv run --frozen python qa/run_prd_tests.py

# 仅用于加快业务逻辑回归；不会改变生产密码配置
uv run --frozen python qa/run_prd_tests.py --fast-passwords

cd frontend
corepack pnpm test
corepack pnpm typecheck
corepack pnpm build
```

默认后端测试保留实际密码哈希算法；`--fast-passwords` 只对当前测试进程替换为快速哈希。浏览器脚本 `qa/prd_browser_acceptance.py` 使用已安装 Playwright 的 Python 启动真实 Chrome，并自行建立、停止独立服务与合成数据库，不复用日常账号。截图和 JSON 检查记录保存在 `.runtime/prd-completion/browser/`。

本轮验收需要分别核对：前端回归、后端回归、新库迁移、浏览器实测和外部服务联调。只有实际运行通过的检查才写入 PR 的验证结果；PostgreSQL 专用并发测试若在 SQLite 下跳过，应单独说明。
