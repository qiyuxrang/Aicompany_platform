## 接班操作

1. 阅读 PHASE1_SCOPE 与 ACCEPTANCE_REPORT，分清运行证据、合成测试、未验证项。
2. 按 DEPLOYMENT 选择 SQLite本地开发、当前 PostgreSQL验证链路或独立 Compose，不要混用配置/卷。
3. 不复制 `.runtime` 或 `backups` 到工单/仓库；它们含随机凭据及完整库内容。正式部署重新配置秘密并限制ACL。
4. 先创建实际操作者账号，不使用 `qa_*` 验收账号。普通管理通过 `/admin/`，不要直接SQL/bulk update权限表绕过审计与epoch失效逻辑。
5. 未批准旧端改动之前，只可完善门户测试、部署和文档。批准后先建立分支/工作树与回退点，保留原项目工作区不动。
6. 后续可信数据验收完成后才可将经营状态从“导航接入”改为“已验证集成”；这个管理字段本身不构成验收证据。

## 回退与停止

新门户故障时停止自己的 Waitress/Compose backend，旧网页与旧登录仍可独立使用。不要停止旧8018或旧数据库。Compose `stop` 保留本期数据卷；不要 `down -v`。代码回退应选兼容现有迁移的版本；数据库恢复到新库、核对、切配置，不覆盖旧业务数据库。当前旧项目没有本期代码补丁，因此不存在要在旧项目撤回的本期改动。
