## 决策与部署边界

- 平台暂名“企业协同门户”，运行于独立目录 `C:\Users\BJRunner\Desktop\ai智能体平台`。
- 受控本机验证入口 `http://127.0.0.1:8100`；正式域名、证书、试用人员名单和业务负责人由公司确认，未虚构已批准的部署位置或人员。
- 保留 React + TypeScript、Django/DRF、Django Admin、独立 PostgreSQL。未新增 django-vue3-admin、django-unfold、react-admin 或 authentik。
- 框架管理界面负责管理，不重复建设另一套 CRUD；平台管理员权限与业务资料权限分离。
- 本期只有“用户 → 多个角色 → 模块”授权，**没有部门组织树或部门级数据权限**。角色名称对应工作职能，不代表部门数据隔离。
- 旧经营、工程、转正项目及其数据库保持原位。导航不代理旧页面、不迁移数据、不访问旧数据库。

## 页面结构

```text
/login                        登录（账号由管理员分配，无公开注册）
/password                     首次/主动改密，成功后全部旧会话失效
/                             工作台：获授权模块及状态、经营接入边界
/modules/:code                授权模块详情、启动、明确待接入/离线提示
/admin/                       Django Admin（仅平台管理员）
  用户 / 角色模块授权 / 模块地址与启停 / 经营用户映射 / 只读审计
/api/*                        相同会话、CSRF、后端授权，不接受浏览器自报角色
/api/integration/redeem/       仅机器凭据兑换服务端票据，无浏览器 SSO
/health/                      平台及独立数据库健康检查
```

## 本期实现与不做项

登录/退出、强密码、首次及重置后改密、多会话失效、账号停用、多角色、后端模块鉴权、平台管理、登录节流、基础审计、可信地址校验、导航健康探测、只读摘要契约、单次短期机器票据、部署与恢复脚本均已实现。是否真实验收通过以 ACCEPTANCE_REPORT 为准，不以代码存在替代验证。

不增加模型调用、Dify、文档生成、通用 Agent、插件市场、任务/成果中心、后台队列或其他业务模块；不重写任何旧业务，不合并数据库，不同时接入四个模块。本阶段验证平台底座，**AI 文档链路尚未验证**。
