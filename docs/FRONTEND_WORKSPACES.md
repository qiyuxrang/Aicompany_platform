## 2. 操作与数据边界

- 表单准备内容仅在组件内存中保存，同一中心切换子页保留；离开中心、切换预览/业务模式、退出或刷新清空。不是持久草稿，不作为正式资料存储。
- 刷新/关页已有未保存输入时使用浏览器离页提示；站内离开中心以页面常驻提示说明清空规则，不宣称所有导航都有确认框。
- 产品非空目录删除、人事登记移除、工程切换有修改的编辑对象均要求确认；工程删除展示对象名称，并在切页时取消未完成删除。必填错误聚焦首项。
- 简历选择只保留文件名，不读取文件内容、不上传、不解析。未实现自动招聘决策，不按个人敏感属性筛选。
- 工程数值输入仅作格式与范围检查，不计算价格合计，不把准备摘要称为正式测算。
- 所有预览只显示人工输入；未接入按钮禁用并说明原因，无样例经营数字、假生成成功或假审批状态。
- 展示操作文案使用中文；账号标识、用户输入、外部数据中的原始名称不擅自改写。

## 3. 权限与撤权

新增页面复用原有角色—模块关系，没有部门组织树或部门级数据权限。产品角色对应 product，工程角色对应 cost，人事角色对应 hr，总经理角色对应 business。

- Django 在返回 `/centers/<code>` 页面前校验登录、改密状态及模块授权；`/preview/` 仅平台管理员可访问。业务接口继续逐请求校验。
- 业务工作台首次进入、窗口聚焦及可见时每15秒发起授权复验；管理员预览同样复验本人身份，但不调用业务模块或项目接口。15秒是检查间隔，不是网络异常时的硬性响应上限。
- 明确撤权、停用或401/403/404会清空该工作区组件；临时网络失败隐藏页面并阻止交互，恢复后保留内存草稿。隐藏不是新的安全边界，已返回给浏览器的内容无法远程收回。
- 复验采用单请求组在途；组内任一请求失败即时隐藏，迟到的明确撤权仍处理，不让网络错误掩盖撤权。
- 经营启动请求在离开原页面/模式时失效，迟到响应不再强行跳转旧系统。
- 平台撤权影响后续门户页面、启动、票据与只读接口；**不默认停用旧系统原生账号，不注销其原生会话。** 原生账号继续受旧系统权限控制。

## 6. 部署与界面回退

本轮只改门户前端与页面访问保护，无新增依赖或数据库迁移。生产域名、HTTPS、网络限制和容量验收不在本轮本地发布内。

实际构建与发布：

```powershell
pnpm --dir frontend typecheck
pnpm --dir frontend test
pnpm --dir frontend exec vite build --outDir ../.runtime/centers-frontend-dist
```

验证后先备份 `.runtime/ops-frontend-dist` 到 `.runtime/centers-preview-backup`，复制新哈希资源，最后替换index。日常配置仍是 `.runtime/ops-validation.env`，数据库仍为 `portal_ops_20260921_085811`。旧哈希资源保留，避免正在打开的页面立即丢资源。18210使用同一配置重启，不执行seed、重置密码或迁移数据。

界面回退只需恢复上一版入口，旧资源仍在；不执行整仓reset或数据库恢复：

```powershell
Copy-Item -LiteralPath .runtime/centers-preview-backup/index.html -Destination .runtime/ops-frontend-dist/index.html -Force
```

恢复后刷新浏览器回到此前界面。新增后端页面保护可保留，旧页面不会使用新增路由。需要重新启动18210时，先核对该端口所属进程，勿停止8100/8018；在工作区设置 `PYTHONPATH` 为 backend，再沿用原环境：

```powershell
$env:PYTHONPATH = Join-Path (Get-Location) 'backend'
uv run --env-file .runtime/ops-validation.env python -m waitress --listen=127.0.0.1:18210 --threads=4 config.wsgi:application
```

该命令是本地前台启动示例，不替代正式进程托管。数据备份/恢复沿用 DEPLOYMENT.md 与20表恢复证据，本轮未重新恢复业务库。
