# 产品事业部招投标商机与准入研判模块设计（待审）

日期：2026-09-23。状态：设计稿，尚未批准实施、真实采集、公司资料接入或生产发布。

## 目标与边界

在现有企业平台内自动发现陕西相关商机、跟踪变更、提示异常，并以可追溯证据辅助人员判断准入与是否跟进。产品 P1「技术方案 Word」与本模块并行，各自验收；P1 的任务、测试或签认不得充抵本模块验收。此模块不生成正式投标文件，不自动报名、投标或作出是否投标的决定。

首批 S1 必须自动接入两个发布范围不同的来源：陕西省公共资源交易平台（https://www.sxggzyjy.cn/）与陕西省政府采购网（https://www.ccgp-shaanxi.gov.cn/）。其余市县、全国汇聚、央国企与行业站点进入扩源台账，逐站核查发布范围、许可和可获取性；不得将首批两站宣称为陕西全量覆盖。公告与完整招标文件分别统计覆盖，无法公开合规取得的文件标记待获取。不绕过登录、验证码、报名、付费或站点访问限制。

## 方案选择

采用现有 Django/React 门户、身份、对象权限、审计及既有后台执行能力；业务对象由平台保存。按来源隔离采集适配逻辑，统一映射公告，不直接合入第三方整套应用。S1 先使用明确规则过滤与来源台账，不引入新的数据库、调度平台或通用工作流；S2 才引入受控结构化资质记录与确定性比较；S3 仅在获授权后接入现有模型网关、受控检索合同和文件解析链路。BidPilot/TenderCrawler 仅供模式参考；代码复用须逐文件核对许可、版本和必要性，BidMaster-Pro 不直接并入主平台。

不采用“先建全套四引擎再上线”的路线：它扩大外部依赖，却不能提高首批公告发现的可验收性。也不采用“只做人工导入”：这不能满足首批自动化目标。

## 业务流程与职责

1. 来源采集定时获取公开公告、澄清/变更、终止及结果信息，记录原始 URL、来源标识、站点公告 ID（若有）、发现及发布时间、原始内容摘要/哈希和获取状态；失败保留错误与上次成功时间。
2. 标准化保留原始内容，抽取标题、采购/招标主体、地区、预算、截止时间、公告阶段及附件入口；未知字段保持未知。单站相同 ID 或链接的重抓幂等；跨站仅在可靠标识或经核对的关键事实吻合时合并；疑似同项目但证据不足时标记待确认，不盲目合并。更正信息作为事件关联原项目，保留先前快照，不覆盖历史事实。
3. 商机池按获准业务范围筛选/排序，展示来源、最近变更和截止时间；字段缺失不被推断为“不适合”。系统不自动决定是否跟进或投标。
4. S2 在公告明确披露准入条件时，对照已核实的企业资质、人员与业绩等结构化资料作预检。每条条件记录原文与定位、提取/确认状态、适用时间、规则版本、企业证据及结果；公告没有披露的条件标待确认，预检不称“完整资格通过”。
5. S3 在获授权且实际取得完整文件后，提取全部相关资格条款，核对提取准确性，再用确定性规则比较；难以结构化的条款交人工判断。检索只用于定位授权证据，模型仅辅助提取和解释。最终由有权限的业务负责人记录是否跟进、理由、操作者和当时的项目/条款/证据版本。

## 判断语义与证据权限

准入条目只有「满足」「待确认」「不满足」：满足要求招标条件及企业证据均已核实且规则可判定；未披露、未取得、未检索到、未核实、抽取冲突、无法解释或时效不明均为待确认；不满足须有可定位的明确不符证据或经授权人员核实的缺失结论。硬门槛不满足单独突出显示，不以 5/6 等比例抵消；软匹配分数不代表投标资格。有效期按招标要求规定的基准日判断，未规定时待确认而不擅定日期。

敏感资质原件、人员证书与合同由服务端按对象和动作授权，商机列表权限不自动赋予原件下载权。来源页面、附件和 OCR 文本视为不可信输入；不执行其中指令，不将无权访问的企业资料送入模型或检索。来源撤权、文件更新或公司证据到期后，原判断保留历史但标记需复核，不继续作为当前满足结论。

## 页面及异常语义

复用产品事业部导航，最小页面为商机列表、项目详情/变更时间线、资格匹配表及来源运行状态。项目详情同时展示公告原文位置与企业证据位置；文件未取得、采集故障、来源无新增、解析失败和权限不足分别提示。来源运行状态展示最近成功时间、失败原因与待处理告警，不用“0 项”掩盖采集异常；告警沿用现有运维入口，避免重建通知系统。

## 分批验收

| 批次 | 交付与必要证据 | 不得宣称 |
| --- | --- | --- |
| S0 来源核验 | 两首批来源的栏目、访问条款、页面/附件可获取性、样本及失败方式登记；扩源台账与缺口 | 所有陕西公告均可抓取 |
| S1 自动发现 | 两来源实际定时运行；重复抓取幂等、跨站同项目核对、变更/澄清留快照、源失败与长期无更新告警；隔离样例及经授权的真实来源观测分别记录 | 自动取得所有招标文件或已经准入通过 |
| S2 公告预检 | 公告条件与核实资料逐项核对；缺失、失效、冲突、无披露及撤权反例；人工纠错留痕 | 公告预检等于完整资格复核 |
| S3 文件复核 | 获授权文件原件与版本、条款定位、企业证据、规则结果、人员复核/决定；越权访问、文件缺失与更正后的重评测试 | 模型自动批准、自动决定投标 |

S1 之后按来源统计成功抓取率、异常处理时延、去重误合并/漏合并抽样；S3 另统计文件实际取得率、条件提取漏报和待确认数量。目标阈值须业务负责人确认后写入验收计划，不虚构 100% 覆盖或准确率。各批次分别出单元/隔离、真实来源、浏览器、业务签认及部署证据，不用上一批或 P1 的通过记录替代。

## 实施前待确认

- 新模块的实施授权：负责人、可写范围、隔离环境与是否允许对两站进行真实自动采集；现有 D-09 不包含该模块。
- S0 核定的站点使用规则、访问频率、允许留存的原文/附件范围；未获许可的来源不启动真实采集。
- 企业资质、人员/合同、业绩资料的权属、确认人、更新职责和保留期限，以及访问与外发授权。
- 后续批次的模型费用、RAGFlow 授权数据集、正式文件获取条件、业务验收门槛和部署恢复要求。
