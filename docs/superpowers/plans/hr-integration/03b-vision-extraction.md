# H3B 平台图片能力与扫描简历识别增量

用户已确认加入本轮实施。原“不做 OCR”仅在本增量覆盖范围内被替代；不增加独立 HR 网关，不固定模型。

## 设计

1. 文本入口 /v1/generate 保持 64KiB；图片入口 /v1/generate-vision 限 6MiB，共用服务鉴权、并发、超时、厂商允许列表、IP绑定与TLS校验。
2. GatewayModel 增 supports_vision 默认 false。门户复用 generate_for_use 和路由权限，带图片时要求该能力，选择图片入口。
3. 只允许用户消息的 text/image_url 块；image_url 只允许 base64 PNG/JPEG 内嵌数据。最多 4 图，单图 1MiB，严禁远程 URL 和 file URL。
4. hr_resume_extract 路由由平台管理员绑定支持图片的模型；不自动将已有文本模型改为支持图片。不配置时返回明确能力/配置错误。
5. PDF 在已有隔离文档运行时逐页检查与渲染。疑似扫描或图片正文页由视觉模型识别整页，替换该页提取文本而非叠加重复内容；保留页号、原件 hash、图片 hash 和提取方式。
6. 页面图片仅按任务权限处理，不进入日志、Git 或公共静态目录。识别不完整、截断、来源变化不得进入匹配，未知不等于岗位不匹配。
7. 第一份低文本量 PDF 只是疑似扫描，不凭字符数认定 OCR 成功；真实验证仅使用用户指定两份文件。厂商可见模型列表不证明图片能力，先合成图兼容测试。

## 顺序与测试

- [ ] RED：文本入口不变；图片入口服务令牌要求、格式和大小拒绝、远程 URL 拒绝、图片透传；门户不支持图片模型调用前阻断。
- [ ] GREEN：共享图片消息校验、网关独立入口、transport 受限序列化、门户能力字段与管理后台。
- [ ] 跑现有文本网关全部回归及图片增量，确认原文本 payload 不变。
- [ ] RED：扫描页判断、分页来源、识别失败不匹配、权限撤销丢弃结果。
- [ ] GREEN：逐页渲染和 hr_resume_extract 路由调用；禁止在未授权读取帮助函数中隐式触发网络。
- [ ] 合成图兼容验证后才对两份授权简历小样本识别，不做大批量真实调用。

## 边界

图片识别输出仍为模型转写，不承诺逐字绝对准确；对低置信度/不可读页记录需人工核对。钉钉与其他 HR 批次继续保持独立。
