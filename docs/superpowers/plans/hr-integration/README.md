# HR 接入与全量验收总计划

> For agentic workers: 使用 executing-plans 按已批准子计划实施；未展开的子计划不是编码授权。

**Goal:** 将招聘业务迁入主平台，按参考图实现 HR 工作台，新增钉钉 360° 问卷及证据化汇总，最后执行全量验收。

**Architecture:** 招聘复用独立 HR 业务模型和规则，平台负责真实身份、权限、审计、私有存储、模型调用及持久任务。问卷评估与招聘分别建模；钉钉仅承担身份和通知，平台保存回答与汇总。

**Tech Stack:** Django/DRF、React/TypeScript、PostgreSQL、现有 FastAPI 模型网关、受控文档运行时。

**Spec:** `docs/superpowers/specs/2026-09-24-hr-recruitment-integration-design.md`

**状态：** 待计划审阅；本次只产出计划。分支 `feature/hr-recruitment-integration`，编制基线 `8929313`。

## Global Constraints

- 独立 HR 仓库仅作读取来源，代码基线 `e85612e`；不迁入用户、数据库、测试业务数据或 storage index。
- 旧 JD 与旧转正记录不删除；旧 JD 必须在服务端拒绝写入，不能只隐藏按钮。
- 所有业务读取、写入、下载和导出按对象归属鉴权；管理员不自动获得 HR 正文。
- 模型调用前处理个人信息；不能以正则匹配成功宣称已经彻底匿名化。
- 不新增人才库，不自动做录用、淘汰或转正决定。
- 不以示例权重、试验并发或固定演示数据冒充业务批准和生产容量。
- 不改其他部门视觉；不自动合并、推送或部署。
- 新依赖、真实人员通知、生产数据迁移分别取得批准。

## Review Focus

1. 身份：不能沿用 FixedIdentityAdapter 或无鉴权 queryset；招聘首批测试其他 HR 和管理员读取返回 404。
2. 个人信息：姓名、自由文本和文件名可能漏脱敏；隐私批次需检验整个出站 payload，而非仅 resume_text。
3. 并发：模型调用期间不持有数据库事务，迟到结果不得落库；Worker 批次需 PostgreSQL 双连接测试。
4. 历史：解析缓存不得跨用户泄露；JD/简历/模型合同/脱敏规则变化须失效；结果批次锁定版本快照。
5. 通知：远端接收后本地超时属于结果未知；钉钉批次须对账或人工处理，不能无限重发或声称 exactly-once。

## 容量设计约束

- 当前网关外发并发 2，Django 单用户最多每分钟 10 次登记调用。两次模型调用/份且无缓存时，后者给出约 5 份/分钟的调用预算上界，不是实测吞吐。
- 本地提取与模型出站分池；模型全局信号量必须覆盖所有 Worker，不是每进程各自允许 2。
- H4 提供 1/2 并发对照，测吞吐、P95、429、重试次数和缓存命中；只有测量证明需要时再提升获准 HR 路由额度，产品路由不变。
- 领取量和实际同时运行量分开；不提前领取大量任务后让租约在队列里过期。
- PostgreSQL 用 skip_locked 短事务领取，网络调用放事务外，每个落库阶段校验 fence/输入版本。
- 分开缓存解析和匹配。缓存包含归属用户、原文/脱敏 hash、解析合同、模型配置和规则版本；匹配额外包含 JD hash。
- 批次进度显示成功、失败、待处理三类计数；处理进度为终态数量/总量，成功率另算。不得照抄参考图中“75%却已完成”的矛盾示例。

## 外部接入与业务确认清单

这些输入不阻塞 H1：

- 钉钉：企业内部应用、可见范围、必要 API 权限、测试 userId、公网 HTTPS H5 地址及实际可用通知/待办接口。逐项核对所选版本官方文档与响应，不沿用此前未成功读取的网页推断。
- 问卷：正式题目、岗位适用范围、上/同/下级关系规则、无法判断选项、截止及最低样本；40/30/30 仅示例，不作为默认批准值。
- 匿名：对被评员工隐藏身份不等于技术完全匿名；小组只有一人或文本提及事件仍可被推断。默认被评员工无原答访问权，敏感汇总只对 HR 开放。
- 隐私：低置信度识别或出站残留个人信息时阻断模型调用，允许 HR 本地检查；不把原文发给云模型来完成脱敏。
- 文档依赖：PDF 提取、XLSX 和钉钉加解密使用可复用的已安装轮子；没有时先申请依赖，不自行写密码算法。
- 视觉：保全两张参考图片为仓库内只读设计资产并校验已登记 hash。品牌图与当前 Logo 不同，实施前确认品牌替换范围，不静默改全平台品牌。

## 全量测试计划 H9

全量自动化与真实验收分别记录，未满足的外部项写 BLOCKED，不因测试替身通过写 PASS。

1. 独立隔离配置运行 Django check、迁移无漂移、迁移计划。
2. 所有 `portal.tests`，新增 HR 测试含在其中；逐条更新旧需求断言，不能删测试掩盖失败。
3. 网关 `python -m unittest discover -s model_gateway/tests -v`。
4. 前端 `pnpm --dir frontend test`、`typecheck`、`build`。
5. 全新隔离 PostgreSQL 库执行迁移和后端全量测试；不得操作日常数据库。未执行 PG-only 测试不得称并发通过。
6. 浏览器：产品三件套；HR JD→上传→筛选→结果/CSV；问卷发放→钉钉身份→填写→汇总→HR结论→XLSX。
7. 安全负向：非 HR/其他 HR/管理员越权、撤权、CSRF、路径、压缩炸弹、PII 出站、导出公式注入、提示词注入。
8. 恢复：领取中断/重复提交/迟到 Worker/通知超时/数据库及文件恢复到新目录；不覆盖原环境。
9. 批量基准：合成 100 份，冷缓存/热缓存、1/2 并发，记录环境和误差；真实样例须单独授权。
10. 汇总失败、跳过、阻塞、通过与原始日志，形成验收报告；业务签认和生产部署不由自动化代签。
