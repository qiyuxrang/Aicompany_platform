# 独立 FastAPI 模型网关

日期：2026-09-21。用户在本轮明确批准新增模型基础层，并指定 FastAPI；保留 React、Django/DRF、Django Admin，不替换门户框架。当前是可运行的配置与网关底座，不是部门 AI 业务功能交付。

## 架构与边界

```text
现有部门业务服务（尚未接入生成等业务）
  → Django generate_for_use(user, purpose_code, messages)
    → 读取用途绑定，检查用户/模块/配置权限
      → 独立 FastAPI POST /v1/generate（内部服务身份认证）
        → 协议适配器 → 获准模型服务

Django Admin → 服务商 / 模型 / 业务用途配置 / 只读调用日志
```

- Django 保存配置与调用元数据，业务模块只传固定用途编码和文本，不接触厂商地址或密钥。FastAPI 不读取门户数据库，也不持有门户数据库凭据。
- Django 每次调用重新读取配置，向网关发送已解析的非秘密配置。网关只信任持有独立服务令牌的后端调用方，不对浏览器开放，不接收客户端自报角色。
- 本期仅支持 `openai_chat` 聊天补全兼容协议；可配置多个 Provider 和模型。不声称任意厂商原生协议都兼容，也不支持图片、工具调用或流式输出。
- `generate_for_use` 是供后续业务服务使用的内部接口，当前没有接入技术方案生成、成本测算、招聘筛选等业务页面，没有新增通用公开推理接口。

## 从哪里配置

使用现有平台管理员账号进入“管理后台”，新增四个入口：**模型服务商、网关模型、业务模型路由、模型调用日志**。

1. 运维人员先把获准服务的规范 HTTPS Base URL 加入 FastAPI 的 `MODEL_GATEWAY_ALLOWED_BASE_URLS`，用逗号分隔；仅443端口、公网地址。本轮不支持私网或本地厂商接口。
2. 在 FastAPI 环境中设置 `PORTAL_MODEL_KEY_公司自定义大写名称`。变量名实际仅允许大写英文字母、数字、下划线，例如 `PORTAL_MODEL_KEY_PRIMARY`。值为 API Key，不要放进源码、URL、聊天记录或日志。
3. 后台新建“模型服务商”：名称、协议、Base URL、**密钥环境变量名**。这是 API Key 的服务端引用，不是明文 Key 输入框；密钥不进入门户数据库或页面。
4. 新建“网关模型”：选择服务商，填写 Model Name、文本能力、超时、输出令牌上限和协议参数名。不同兼容服务可选 `max_tokens` 或 `max_completion_tokens`，真实兼容性仍需测试。
5. 保存后勾选费用确认，点击“测试连接”。测试仅发送固定短文本，最多16个输出令牌且不超过配置上限，不展示模型输出；停用配置也允许管理员先测试。
6. 验证后启用服务商和模型，为业务用途配置“业务模型路由”，绑定既有模块和模型。所有新配置默认停用，不预置虚假可用模型。

切换已获准、密钥已加载的 Provider/模型，只需修改用途绑定，不改业务代码、不重启服务。**新增/轮换环境密钥或修改外发允许名单，需要重启 FastAPI 进程**；这不等于业务代码修改。新增服务仍必须先获准外发目标。

后台外键下拉显示名称和编号；后台变更日志仅保留对象编号、变更字段名，不写配置值。模型调用日志只读，普通用户不能配置或执行连接测试。管理员身份不自动授予部门业务权限。

## 安全与失败处理

- 门户到网关：独立随机服务令牌，精确内部 URL 允许名单；本机只允许回环 HTTP，Compose 仅放行固定内部 `http://model-gateway:18410`。远程部署必须明确配置 HTTPS 地址和允许名单。
- 网关到厂商：精确 Base URL 白名单、全部 DNS 结果公网校验、绑定已校验 IP 建连、按原始 hostname 校验 TLS；不跟随重定向、不读系统代理、不自动重试。
- 输入只接受限定角色的纯文本消息；请求体最多64KiB，厂商响应体最多1MiB；验证 JSON、文本输出及可选用量字段。未知用量保持空，不伪造0或费用。
- 单 FastAPI 进程最多2个外发调用；生产启动固定一个 worker。单账号每分钟最多10个登记调用，同一账号对同一模型每分钟最多1次连接测试。它不是企业级配额/预算系统。
- DNS、连接、TLS、响应读入纳入请求期限。操作系统 DNS 调用无法强杀，超时后最多占用2个守护工作线程，不无限创建线程。
- 调用前核对用户、业务模块和启停状态；返回前再核对账号状态、授权版本和服务商/模型/用途配置更新时间。调用期间撤权或配置变化时丢弃结果，包括撤销后恢复的情况。
- 已经发送给厂商的请求不能撤回，也不能保证取消费用；停用或撤权阻止后续调用并阻止失效结果交付，不宣称取消上游执行。
- 日志不保存提示词、模型输出、API Key。调用日志保存结果码、耗时、服务返回的令牌计数。进程异常退出可留下“处理中”记录，不能视为成功。

## 运行方式

本地网关环境文件 `.runtime/model-gateway.env` 与门户 `.runtime/ops-validation.env` 分离，并限制为当前用户可读写。参考 `model_gateway/.env.example`；占位项不构成可用凭据。

FastAPI 环境：

```dotenv
MODEL_GATEWAY_SERVICE_TOKEN=填写独立随机令牌，至少40字符
MODEL_GATEWAY_ALLOWED_BASE_URLS=https://approved-provider.example/v1
MODEL_GATEWAY_CONCURRENCY=2
PORTAL_MODEL_KEY_PRIMARY=由运维配置真实密钥
```

门户环境（不要放厂商 API Key）：

```dotenv
PORTAL_MODEL_GATEWAY_URL=http://127.0.0.1:18410
PORTAL_MODEL_GATEWAY_ALLOWED_URLS=http://127.0.0.1:18410
PORTAL_MODEL_GATEWAY_TOKEN=与网关一致的独立随机令牌
PORTAL_MODEL_MAX_PENDING_PER_MODEL=4
```

`MODEL_GATEWAY_CONCURRENCY` 和 `PORTAL_MODEL_MAX_PENDING_PER_MODEL` 均只接受 1 至 100；默认值分别为 2 和 4。业务路由还可在管理后台单独设置每个用户每分钟的调用上限（1 至 120）。

启动本地网关：

```powershell
uv sync --frozen
.\scripts\start-model-gateway.ps1
```

该命令前台运行，关闭后不影响门户基础功能；本轮实际启动使用隐藏后台进程。门户仍使用既有日常环境，加入配置后需重新启动其进程。

Compose 为可选 `models` profile，不会被普通默认启动自动启用。先按原部署文档配置数据库、门户、HTTPS反代，再设置门户网关地址为 `http://model-gateway:18410`，其允许名单也填该精确值，并使用独立 `MODEL_GATEWAY_ENV_FILE`：

```powershell
docker compose --profile models up -d --build
```

网关容器无宿主端口、不挂数据库卷、不引用门户 env；一个 worker，最多2个外发调用。镜像使用同一锁文件，但进程、配置及数据库访问边界分开。`/health` 只表示进程存活，不表示服务令牌、厂商密钥或模型可用。

依赖锁定在 `uv.lock`：FastAPI 0.141.1、Uvicorn 0.53.0、Pydantic 2.13.5、Starlette 1.6.0；测试依赖 HTTPX 0.28.1。没有引入厂商 SDK 或额外编排平台。测试客户端存在HTTPX兼容接口弃用提示，目前测试通过，未为消除提示额外更换依赖。

- PostgreSQL 后端全量回归，以及 FastAPI/传输协议单元测试；最终数量以归档日志为准。
- 真实本地 Django → FastAPI HTTP 联调13项通过：服务鉴权、后台创建配置、CSRF、测试费用确认、无授权外发目标拒绝、用途授权、撤权和日志只读。
- 多 Provider 与用途切换的成功返回通过协议模拟测试验证；**没有获准厂商密钥，尚未验证真实厂商成功推理、真实用量和质量/成本**。
- 原前端195项回归通过；本轮不改页面风格、账号密码或既有业务权限。
- 两轮本地HTTP验收各创建2个隔离账号，结束后停用、设为不可用密码、清理会话及服务令牌；测试服务已停止，隔离数据库保留。
- Compose 配置校验通过；本轮未重建启动 Compose 全栈、未验证公网 HTTPS、普通浏览器完整流程、负载容量或企业多节点限流。后台交互采用真实 HTTP/CSRF 验证，不冒充浏览器验收。
