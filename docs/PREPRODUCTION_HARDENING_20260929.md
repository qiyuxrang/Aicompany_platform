## 批次二：文档渲染与恢复

### 已定位根因

既有失败样本包含 496 个报告内容块，而 PPT 脚本上限仅为 400；子进程以 `invalid slide source` 退出，被上层折叠成 `presentation_unavailable`。本轮修复此具体不匹配，保留有界限制：来源 JSON 最多 16 MiB、内容块最多 10,000、单块文本最多 100,000 字符，并验证来源类型、标识及版本结构。

诊断只保存白名单阶段、原因、退出码和栈帧，不保存原始 stdout/stderr、异常消息、提示词或报告正文。依赖缺失、启动失败、超时、来源超限、渲染失败、缺失清单和质量检查失败可区分。

### 恢复与证据真实性

- 回归验证两份 Word 已生成、PPT 失败后，通用重试复用已有 Word 的记录与哈希，不重复渲染或覆盖已有 Word；模型审核仍按原流程执行，不把文件复用宣称为所有模型步骤均免调用。
- PPT 以当前报告内容制作摘要，图表数量来自实际来源，不固定声称“15/20/35 张”。摘要只记录实际选用内容块；未选用内容与未知引用分开计量，不以引用目录冒充全文内容覆盖。
- 来源与质量清单严格验证字段类型和集合一致性；`draft_unverified`、`content_review=not_run` 和业务批准边界保留。
- Office 预览审计须允许本平台原生图表使用的安全、内部引用的无宏 XLSX，同时继续拒绝宏、外链、嵌套 OLE/活动内容及超限压缩包；不能通过整体关闭审计解决预览失败。
- 独立复审发现并封闭两种伪装：按 ContentType 而不只按扩展名识别工作表 XML，拒绝改名后的公式；对所有包类型检查活动 ContentType 与关系，拒绝伪装成普通二进制部件的 VBA。

三种合成 PPT 输入覆盖小报告、超过旧上限的长报告、带待确认项的报告。它们验证渲染和来源约束，不验证业务结论质量。既有失败样本仅在新私有输出目录重放，不改写原任务状态。

## 可复现验证

安装仓库锁定的依赖后，在 Windows 项目根目录执行：

```powershell
./qa/run_preproduction_checks.ps1
```

该入口运行隔离后端、迁移检查、模型网关、前端组件、类型检查及构建。每次日志和前端构建写入独立 `.runtime/preproduction-checks/<run>/`，不覆盖常驻 Web 服务使用的 `frontend/dist`。命令运行前按白名单清理继承环境，前端使用空环境文件目录，Corepack 禁止自动联网下载；退出时恢复调用进程环境。它不做生产数据库迁移、不启动模型计费任务、不发布或重启生产服务；这不是操作系统级网络沙箱。

本机已有独立文档运行时与 Office 时，可追加全长度合成验收（不自动安装依赖）：

```powershell
./.venv/Scripts/python.exe qa/run_preproduction_document_acceptance.py --timeout 300
```

若文档运行时或 Word 渲染不可用，该脚本不会报告完整验收通过。PPT Office 预览是本轮额外的私有样本重放，不包含在此长文脚本的自动执行范围。

针对性回归可执行：

```powershell
uv run --frozen python qa/run_prd_tests.py --fast-passwords portal.tests.test_engineering_api portal.tests.test_product_required_knowledge portal.tests.test_product_presentation_recovery portal.tests.test_preproduction_business_acceptance
```

本机还保留 `.runtime/preproduction-20260929/` 中的私有样本重放、浏览器截图、Office 预览及交叉复审验证记录。独立文档运行时缺失时，相关测试明确跳过；跳过不等于通过。
