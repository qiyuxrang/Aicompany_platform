| 1. 平台内可见（最优先） | 在产品侧栏增加「商机获取」；选择性接入公告、来源、快照/版本模型和只读 API；迁入列表、筛选、详情、官方链接、来源状态页面 | 产品账号能从 `/centers/product/opportunities` 查看授权公告；未知字段如实显示；无数据、无权限和来源故障区分；关闭采集仍能看已入库公告；管理员预览不读取业务数据 |
| 2. 异步刷新闭环 | 复用四来源适配、安全出站、去重和失败隔离；刷新请求只入队，由专用消费者处理并回报状态；修正/验证全国采购网首次运行疑似跳过公告的问题 | **零真实外站**的隔离演练通过“点击→入队→消费→轮询→合成公告出现”；重复执行幂等；开关关闭时不入队、不出站；来源异常不显示为正常空结果。完成隔离数据库迁移、权限、CSRF、原文 URL、产品回归及浏览器冒烟，作为门槛 A |
| 3. 受控真实样本 | 另获许可后逐站核验栏目、发布时间、扫描范围、详情正文和官方链接；按固定首次窗口受控采集并校准字段；验证后台人工刷新 | 每条真实公告有来源、日期依据、原文 URL 和采集记录；复跑不重复；未覆盖窗口、合法空结果、站点失败分别报告。无合格样本不造数、不扩大窗口。逐站批准且 A 通过后做门槛 B |
| 4. 正式运行 | 审核目标库迁移、备份、私有快照存储、消费者启动/心跳/告警、开关、停采与回退 | 产品用户看到已核实公告；仅当后台确实能消费时开放刷新；异常可追踪，权限撤销立即生效，旧公告/审计保留。业务签认和部署单独批准，作为门槛 C |
| 5. 公告预检（S2） | 对已披露并核实的公告条款做定位、硬软分类；经授权管理企业资质/人员/业绩证据，仅用获批确定性规则比较 | 按“满足／不满足／待确认”逐项展示双向依据；未披露、无命中、证据未核实或到期不得标满足；硬门槛不满足单独提示；公告/证据变化使旧结果待复核。先确认企业资料权属、权限、有效期与规则 |

## 四、页面和数据链路

1. **商机池**：按来源、地区、采购方、类型、日期和状态筛选；展示标题/编号、预算、截止时间、发布时间、最近变化、来源健康。未知值显示“未知”；空库、筛选无命中、采集失败分别提示。
2. **商机详情**：展示原公告、更正/补充/结果事件、版本差异、采集时间、已核验的对应官方详情页和允许访问的附件；不从标题拼接或猜测原文 URL。
3. **来源与刷新状态**：展示最近尝试、最近成功、排队/执行/失败和刷新结果；普通用户不见站点凭据或内部错误。刷新是异步请求，不在 HTTP 请求内爬取。
4. **资格匹配**：阶段 5 才显示“公告预检”；阶段 6 取得完整文件且核实条款后才显示“完整文件复核”。逐项显示原文、定位、企业证据、结论及待复核状态；不以占位页宣称交付。

采集链路：`官方公开公告 → 许可范围内的站点适配器 → 原始快照与字段归一化 → 来源内去重、版本及事件 → 平台数据库/API → 产品事业部页面`。刷新链路：`页面 POST → 数据库批次入队 → 独立消费者 → 批次状态与公告更新 → 页面轮询`。企业资料与资格结果单独授权，不插入产品项目成果任务，也不直接修改经营台账。

## 五、实施约束、验证和停点

- **可复用**：原型四站适配、安全出站、结构化、快照/事件、前端列表详情与测试思路；平台产品权限、审计、CSRF、Django/React 工作台。目标仓库要重新验，不能直接复制原型迁移、旧库数据或开发配置。
- **必须补验**：官方原文与公告对应、真实字段准确性、固定窗口覆盖、幂等与进程恢复、撤权、隔离 PostgreSQL 迁移、平台产品功能回归；原型测试通过不等于目标平台验收。
- **默认关闭**：真实外站采集和人工刷新分别设受控开关；不开周期自动采集，不另建门户、登录、审批或消息中间件。来源禁止访问或不可达时停该站，保留错误和最后成功时间。
- **每阶段留证**：变更清单、页面/接口效果、测试结果、未完成项及下一阶段所需批准；“页面可打开”不等于真实采集或正式上线。
- **必须另行确认**：来源访问及保存许可、真实出站与首次采集窗口、企业敏感资料及模型外发、生产部署与消费者常驻、超出固定窗口的补采、每个新增来源。本文不是这些行为的授权。
