# 总经理看板与源表导入

## 页面

- 桌面总经理工作台采用导航约 1/5、正文约 4/5 的比例；导航纵向展开，移动端仍可折叠。
- 首页为“数据分析 / BI 报表看板”，顺序为财务、产品事业部、工程；图表仅出现在首页。
- 部门页仅显示原表字段、明细、搜索、来源工作表筛选、更新状态和版本；长文本可展开，宽表可横向滚动。
- 总经理仍为只读身份，部门录入、提交和发布权限未放宽。

## 财务字段与口径

来源为 `应收账款盘点表2026（更新后）.xls` 的“应收总账”。

保留类型、项目、业主单位、挂靠单位、合同金额、年初应收总额、实际应收结余、1—7 月已实现回款、8—12 月计划回款、挂账主体、回款负责人、目前状态，并附来源工作表、行号和系统记录编号。仅展开原表真实合并单元格，不对普通空白做向下填充。

24 条项目记录，不包含合计行。财务金额按原表显示口径转为两位小数，以 Decimal 计算并逐列核对 15 个金额列的合计。实际应收结余直接来自原表；不使用“合同金额减已实现回款”倒推，不从备注推断逾期日期。原表没有的全生命周期已收金额、应收日期保持空白。源表错误、合计不一致或截断字段均阻止首次导入。

## 产品字段与口径

来源为 `产品事业部=能源组内部工作管控 (2).xls`。

以跟进项目、跟进时间、项目定型、项目进展、项目概况、项目额度、跟进人员、甲方对接人、成熟度为核心，同时保留工作表、来源分组、原序号、行号、原始额度和单位、推进计划、预计签约时间、备注及连续跟进历史。

同名项目可能分布于多个工作表，原始记录不合并或删除；记录编号由工作表和原始行生成，而不是使用存在重复的业务序号。部门项目列表按空白规范化后的同名项目分组，详情可切换全部来源记录；首页条目数量不是去重后的独立项目总数。仅在原表明确标明“万元”时换算为元；其他空白或不明确额度不补零、不猜单位。已签单金额和预算不得相加冒充营业收入或销售预测。

## 首次导入

管理命令默认仅预检，要求两个文件、明确盘点日期和一个已有的有效总经理或平台管理员账号：

```powershell
uv run python backend/manage.py import_business_workbooks `
  --finance "<财务 XLS 绝对路径>" `
  --presales "<产品 XLS 绝对路径>" `
  --actor "<已有操作人账号>" --as-of 2026-09-29 `
  --publish --report .runtime/business-import-preflight.json
```

执行前需加载当前本地环境配置；引号包围的环境变量值需去掉外层引号。预检无误后追加 `--apply` 才写入。`--publish` 表示按用户授权将本次原表快照发布到总经理看板，不代表对原表业务数据做了财务审批。

命令仅在本地 SQLite 上执行首次写入：自动备份数据库、在一个事务内写入两部门数据、保留导入/提交/发布三次不可变版本和审计记录。完全相同的重复导入不再写入；不同的已有台账一律拒绝覆盖，后续更新须走既有部门台账流程。不会创建或修改账号、密码、角色、台账授权，也不写入工程数据。包含原表备注等内容的核验报告仅写在忽略版本控制的 `.runtime` 中。

`as-of` 是本次盘点快照日期，不代表历史条目或源工作簿的最后业务更新日。页面另行显示发布/更新时间及原始跟进日期。
