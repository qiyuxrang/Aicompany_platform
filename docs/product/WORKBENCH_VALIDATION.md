## 前端与后端防回归重点

创建请求结果不明时冻结请求体与幂等键。多个附件部分失败后仅重试剩余文件，不重复创建项目；上传响应丢失时仅凭新增文件 ID、名称、大小及 SHA256 的一致性确认成功。陈旧请求会被中止，不覆盖新项目或新查询。

蓝图与底稿编辑保留自己的基准版本。服务器出现新版本时，保留本地输入、阻止直接覆盖。蓝图审批绑定 ID/hash，需要明确核对勾选和审核意见。页面通过后台 actions/blockers 控制按钮，后端仍独立鉴权。

排队或执行中的任务不允许从业务接口更换输入、蓝图或重复排队；取消需要明确操作。空闲项目重新获得窗口焦点或定期检查时会核验对象访问权，撤权后隐藏资料。旧成果单独标记并从历史入口下载，不代替当前成果。

## 指标口径

统计仅限当前账号拥有或被指定审核、且当前输入来源仍获授权的项目。“进行中”包含未完成且未取消的任务；“待审核”来自 `WAITING_REVIEW`；“编制中”来自正文/检查/渲染阶段且尚未结束或进入审核。

“本月完成”目前以已完成任务的 `updated_at` 作为完成月份，首页卡片与列表筛选使用同一口径。未来允许完成后变更项目元数据时，应引入独立 `completed_at` 字段，避免把后续元数据变动算成新的完成月份。

## 复现与证据

使用本仓库现有 Python 3.13 环境和前端锁定依赖。文档生成另按原运行手册创建 Python 3.12 环境：

```powershell
uv venv --python 3.12 .runtime/product-documents-python
uv pip install --python .runtime/product-documents-python/Scripts/python.exe -r backend/portal/product_assets/document-runtime.txt
```

后端测试须使用独立测试环境，不能向日常数据库执行种子或验收脚本。前端运行 `pnpm --dir frontend build` 与 `pnpm --dir frontend test`。本机 pnpm 全局启动器的版本缓存缺失，验证通过 `npx --yes --package=pnpm@11.10.0 pnpm ...` 使用锁定版本，没有修改仓库依赖。

真实浏览器复现：先用 `.venv/Scripts/python.exe qa/product_workbench_server.py` 启动独立服务；再用已安装 Playwright 的 Python 运行 `qa/product_workbench_browser.py`。脚本限定 `127.0.0.1:18743`、每轮创建独立数据库、生成随机合成账号、强制关闭模型/检索/正式发布。必须每次启动新服务后再运行浏览器流程；用 Ctrl+C 停止该验收服务。脚本不要求或读取真实用户密码。

本机证据路径（不提交凭据、测试数据库或依赖目录）：
