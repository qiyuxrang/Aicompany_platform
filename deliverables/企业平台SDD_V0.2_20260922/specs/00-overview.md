# 总体需求与产品定位

V0.2文档修订已授权；本文件明确设计方向，不替代下一轮代码范围、外部数据处理及正式上线批准。

## 产品定位

面向企业多部门的AI业务协同平台，以任务为中心，将知识检索、生成、人工审核与成果留痕连接为可控交付流程。员工从产品、人事、经营或工程入口工作，不需要操作模型配置、Skill或编排图。任务列表、待我审核、近期成果为通用交互方向，复用既有工作台而非重做首页。

不构建通用WorkBuddy替代品，不允许普通用户安装任意Skill、执行任意脚本、访问任意本地文件或连接任意工具。复用原Skills中的业务规则与工具，但运行不能依赖WorkBuddy宿主。

任务内自然语言修改可作为后续交互选择：解释为变更建议，展示影响，需要时确认，再走同一服务接口；不能凭模型口头“已批准”改变状态。本版不新增通用聊天入口或对话执行需求。

使用者包括作者、蓝图/成稿审核人、HR、主管、经营用户与平台管理员。管理员不天然拥有业务正文，总经理经营权限不自动包含人事资料。

## 分期与边界

| 发布包 | 目标与现状 | 条件 |
| --- | --- | --- |
| G0 公共基线 | 门户、权限、运维和网关已有基础，仅补业务差距 | D-03/D-08/D-09；不重建已验证能力 |
| P1 产品首期 | 一种技术方案Word；整体部分完成，已有隔离增量，真实业务待验收 | D-01/D-02/D-03及相关部署条件；新增留痕与质量回归纳入后续差距 |
| P2 产品扩展 | 同源可研和PPT，独立模板与验收 | P1通过，相应模板及样例获批；本轮不启动 |
| H1 人事招聘 | JD与简历分析分批；当前批次不开发 | 身份/许可、样例；仅正式评分依赖D-04 |
| H2 人事转正 | 复用原状态机与审批服务 | D-03/D-07/D-08；不强制依赖H1 |
| B1 经营接入 | 保留导航/项目摘要；扩展真实授权看板 | 旧端改动授权、口径及来源对照；不重算财务 |
| E0 工程盘点 | 一个专业的资料、依据、样例与交接 | 造价负责人，不产生正式定额结果 |
| E1 工程试点 | 获准范围内核查、推荐、人工审定与交接 | E0和D-05完成，不猜测计价规则 |

实施路线：公共底座复用→产品P1闭环→留痕与质量控制补齐→分批接入人事/经营/工程→试用与统一优化→正式部署。基础留痕从每次修改起记录，不能事后补造历史。参赛展示可在产品真实验证后并行准备，不改变整个平台目标，不需要等待所有部门完成。

每批先功能后细调；权限、数据正确、批准、成果保存和格式正确不是后期美化。只阻塞依赖未确认条件的任务，其他获批工作可继续。

## 数据和状态权威

| 内容 | 权威来源 |
| --- | --- |
| 账号与模块权限 | 平台Django；各业务继续核验对象/动作权限 |
| 产品任务、版本与人工批准 | 平台业务记录；worker/编排检查点不替代批准 |
| 事实与验收条件 | 任务内已确认来源、条件版本与人员决定；来源有引用不等于事实正确 |
| 文档成果 | 不可覆盖的版本工件与精确批准关系；哈希只证明字节一致 |
| 知识索引 | 复用原有RAGFlow；平台当前仅内部合同已接线，原生适配和授权联调待完成；非实时业务账本或权限决策替代品 |
| 人事与经营数据 | 原业务服务及其数据库，不合库、不维护第二套评分或财务账 |
| 工程计价 | 获准规则/专业工具与造价人员审定，不由模型认定 |

## 变更与完成定义

先批准任务范围与适用决策，再实现、验证、审查和验收；普通实现自主推进。变更记录原因、REQ/AT/任务及回归范围，不以删规则或降低门槛掩盖失败。全部适用AT、权限负向测试、业务确认及回退条件满足才算对应包完成；导航、机器API、SSO和真实模型验证分别报告。
