## 1. 目标、边界与硬约束

目标：自动发现陕西目标商机，可靠展示公告变更与来源异常；对公告阶段和完整文件阶段分别给出可追溯的资格判断，辅助有权人员决定是否跟进。

- S1 **必须**自动监控两个首批来源：陕西省公共资源交易平台 `https://www.sxggzyjy.cn/`、陕西省政府采购网 `https://www.ccgp-shaanxi.gov.cn/`；S0 须先核实真实栏目、许可和可访问路径，不预设任何内部接口稳定或可公开取附件。市县、全国、央国企、行业平台列入扩源台账，另批逐站接入。两站成功不称“陕西全覆盖”。
- S2 是**公告预检**；S3 是**取得完整文件后的资格复核**。公告没有披露的条款、未取得文件、未核实的公司材料、检索无命中，一律不得显示“满足”。
- 系统不得代替人决定是否报名、跟进或投标，不自动报名/提交/出价/发布投标文件；只提供证据、状态和提示。
- 仅在站点许可及授权范围内采集公开内容；不绕过登录、验证码、报名、付费、反爬或授权限制。没有权限时标记「待授权／待获取」，不得偷偷换源绕过。
- 复用本平台现有 React、Django、身份/对象权限、审计、部署/日志/运维、模型网关和受控检索合同；不得另建门户、通用 AI 工作流、第二套审批/审计/检索或直接部署开源项目。现有 `run_product_worker` 属于 P1 专用执行器，不预设可作为招投标定时调度器。第三方代码仅在逐文件复核版本和许可证、获批准后复用。

## 3. 采集技术原则与待决事项

以下固定的是**采集原则和验收合同**，不是框架选型，也不改变 A0～A4 授权关卡：

1. 每站独立适配并输出统一、可验证的 Notice/Snapshot 输入；不得共享脆弱的站点解析规则。仅在 S0 核实路径和许可后，按实际情况选择已获准公开 API、普通 HTTP/HTML，确实依赖 JS 时才考虑浏览器渲染；三者均不得绕过登录、验证码、报名、付费、反爬或其他访问限制。
2. 结构化字段只来自实际取得且可信的页面、公开响应或已核实原文；保留来源 ID、原始公告 URL、字段原文、获取时间、受权保存的内容版本/哈希及逐字段解析状态。未披露、乱码、解析失败或来源不可信时保持未知，不能用 AI、规则或其他来源补造本站字段。无法受权保存原文时记录限制，不虚称已有快照。
3. 更正、澄清、终止生成新快照或事件，保留旧版；抓取失败不覆盖历史。附件不作为 S1 公告发现成功的前提：先记录可合法展示的入口及待获取状态，仅在后续业务阶段且获得权限时按需获取。单站故障不影响其他站点的数据和执行。

**S0 后才确定实现**：每站是否需要 Scrapy、轻量 HTTP 客户端或浏览器、解析库及目标 Python 3.13 环境兼容性；S1 批次再冻结调度、并发领取、幂等、来源隔离、超时/重试与 Django 数据层交互并单独验收。优先复用现有部署/日志/进程管理能力，但不能把 P1 worker 当作已验证的通用定时器，也不为未证实的扩源规模预装依赖。

## 4. 数据合同与状态（逻辑模型，不强制一对象一表）

| 对象 | 最少字段和不变量 |
| --- | --- |
| Source | 来源 ID、站点/栏目、许可/采集状态、允许频率、最后尝试/成功时间、异常原因与处理人；单站停用不得影响其他站 |
| Notice | source_id、站点公告 ID（若有）、原始 URL、公告阶段、发布时间/抓取时间、标题、采购人、地区、预算、截止时间、文件入口与各字段提取状态；不可信字段保留未知而非补造 |
| Snapshot / Event | 原始内容受权保存位置/哈希、版本与获取时间；变更/澄清/终止关联项目并保留旧快照；抓取失败不得覆盖旧数据 |
| Opportunity | 内部稳定项目 ID、来源公告关联及人工核对记录；疑似重复未确证时不能强制合并 |
| Evidence / Requirement | 阶段（公告/完整文件）、要求原文、条款位置及文件版本、提取/核实人、规则版本、企业证据 ID/版本、核实状态及适用基准日期 |
| Assessment / Decision | 每条资格结果、原因、证据版本、评估时间、过期/需复核标记；跟进决定仅记录经后端鉴权的真实操作者、动作、理由及当时版本 |

接口契约：采集适配器只把公告/变更映射为统一的 Notice/Snapshot 输入，不直接变更资格判断；业务服务负责幂等、合并、状态机与审计；UI 只能通过服务端授权 API 看结果和原件，不能从浏览器直连站点凭据、模型或知识库。新增 API 的具体路由和字段先对照现有实现冻结为实现批次合同与负向用例，不以设计稿强制命名数据库表。

资格条目三态：**满足**＝招标条件已核实、企业证据有效且适用、确定性规则明确成立；**不满足**＝有可定位明确相反证据，或有权人员依据受控完整记录核实缺失；**待确认**＝未披露/未取得/未核实/冲突/规则不支持/时效不明/检索未命中。规则不以“未搜到”为“不满足”。硬门槛任一不满足必须单独提示，不得由满足比例或软评分抵消；判断基准日按文件条款，未规定则待确认。源或公司证据撤权、更新、到期后历史不删除，但当前评估标需复核且不继续显示为已满足。

## 5. 可执行任务、依赖与验收（一次只执行获准批次）

### S0 来源与平台基线 — T-TEN-00

1. 只读映射已有产品导航、后台任务/调度、审计、模型、检索、文件及运维能力，避免重建；记录本地未提交改动。
2. 分别登记两个首批站点的**实际**公告/更正/结果栏目、地区过滤、翻页、附件访问和公开访问规则；保留合法可访问的抽样链接、时间和无法访问原因。制作扩源台账（市县/全国/央国企/行业），标注与省站重复风险，不推断全部覆盖。
3. 给出每站获准采集范围、周期、超时/重试/停采界限及负责人的书面确认；记录 API/HTML/JS 路径与目标 Python 3.13 环境的技术验证结果，无法验证时保持待决；无确认不进入真实采集。

**AT-TEN-00**：每站都有可复查来源记录和授权/阻塞结论；站点不可用或未授权时明确阻塞真实采集，不编造接口或样本；平台现成能力及可复用文件有实际代码定位。

### S1 自动发现与变更追踪 — T-TEN-11～14

- **T-TEN-11 来源适配**：在隔离夹具中分别解析两站公告及变更，严格校验 URL/字段/时间；不得请求非获准域名、内网地址或根据附件重定向越权获取。生产采集仅在 A1 获准后启动。**AT-TEN-11**：两站各有公告、无数据、结构变化、超时、非法链接/重定向样例；一站失败不造成另一站数据消失。
- **T-TEN-12 存储与合并**：按站点公告 ID 或规范化原始 URL 做站内幂等；跨站仅在可靠标识或经人工核对的关键事实一致时合并。变化保存新快照/事件，旧版可追溯。**AT-TEN-12**：重复抓取无重复项目；跨站相同项目正确关联；同名不同主体不误合并；更正截止时间可见、旧值仍可追溯；失败不改历史。
- **T-TEN-13 定时执行与告警**：优先复用现有部署、日志和运维能力；调度、并发领取及单站执行隔离须在 S1 单独设计验证，不预设复用 P1 worker；保证重复执行不会重入破坏数据，记录每站尝试、成功、解析失败、长时间无更新及停采状态。异常阈值在 A1 确认，不能用“零商机”掩盖故障。**AT-TEN-13**：定时运行两站、单站故障及恢复、连续空结果与结构变化均能被区分并触发可见异常；留运行记录及告警处理证据。
- **T-TEN-14 产品页**：现有产品导航增加商机池、项目详情/来源变更和运行状态；支持加载、无新增、故障、未授权的不同提示。**AT-TEN-14**：浏览器可从产品入口查看两个来源的公告和变更；无权用户直接调用详情/原始附件接口被后端拒绝，不泄露敏感元数据。

S1 不依赖完整企业资质库；交付必须有两站真实定时观测（在 A1 授权后）与隔离反例，只有夹具不称 S1 真实来源验收通过。附件不可取不阻塞公告发现，但状态必须为待获取。

### S2 公告阶段资格预检 — T-TEN-21～23

- **T-TEN-21 受控企业资料**：在 A2 许可范围内记录企业资质、人员证书、业绩等结构化事实、原件引用、确认人、主体、适用地区/业务、等级及有效期；原件按对象/动作授权，读取、撤权和更新留痕。**AT-TEN-21**：跨部门越权读/下载被拒绝；过期、主体不符和未核实材料不能支持满足结果。
- **T-TEN-22 条件预检**：仅处理公告已披露且已核实的条款；条款含原文/定位、硬软类别和规则版本。确定性比较级别、地区、期限、业绩数量/金额等**已获业务批准**规则；无法解析或未披露的要求交待确认，不能推测公司不具备。**AT-TEN-22**：级别高于最低要求且其他约束齐全可满足；明确过期/主体不符为不满足；无公告条件、仅搜索无命中、人员信息未知均待确认；一个硬门槛不满足时卡片不能展示总体合格。
- **T-TEN-23 人工复核与版本失效**：有权人员纠正公告条件或资料并写原因；规则/证据/公告变更触发重评，历史结果留存，当前显示待复核。**AT-TEN-23**：撤权、变更截止日、更新证书后旧满足不沿用；未获权人员不能覆盖结果或代替负责人决定。

S2 的产品用语只能是“公告阶段预检”，不以公告未出现某条件声称“资格完整符合”。

### S3 完整招标文件资格复核 — T-TEN-31～33

- **T-TEN-31 文件取得与版本**：公开且允许保存的附件按 A1/A3 授权获取；需报名、付费、登录或验证码而未授权者只记录入口/状态，允许有权人员补入已合法取得文件。校验文件实际格式、大小、归属、哈希及版本；不执行文档内指令/宏。**AT-TEN-31**：未取得文件不得发起“完整复核”；换文件版本使旧结论失效；无权限用户不能下载原件或以他人项目 ID 读文件。
- **T-TEN-32 条款提取与证据匹配**：在 A3 授权下复用模型网关/现有检索合同，模型提取的条件和页码/段落先由人核对再生效；检索到的材料需核实版本与权限，不能仅凭模型自述定准入。确定性规则只判断可解释条件，其余待确认；保留招标条款及公司证据双向定位。**AT-TEN-32**：缺页、OCR 失败、来源冲突、授权拒绝、检索超时/无结果分别可见；伪造引用不得判满足，未授权公司资料不得进入模型请求；明确相反证据可判不满足。
- **T-TEN-33 人工决定与审计**：有权负责人阅读当前精确项目/文件/证据版本后记录跟进、暂缓或忽略及理由；模型/worker 无决定权限；后续版本变更提示决定依据过期，不覆盖历史决定。**AT-TEN-33**：伪造角色、旧版本决定及模型自动提交被拒绝；审核人与系统提取者、操作者可区分；更正公告或替换文件后显示需重新核对。

### S4 扩源与质量 — T-TEN-41～42

按 `annex-01-S4-expansion.md` 逐站引入市县、全国汇聚、央国企和行业采购来源，逐来源重新核对 A1；由 T-TEN-41 验证新站点隔离与合法可用性，T-TEN-42 基于已批准栏目/时间窗抽样评估覆盖、去重与文件获取质量。可在 S1 稳定且单站获授权后与 S2/S3 并行，不能把 S0 台账当作 S4 接入完成。

**AT-TEN-41/42**：每个新增站点分别出合法样本、接入及失败隔离证据；以适用抽样窗口报告漏抓、重复、误合并、解析错误与文件可取得率。未确认质量门槛只报告观测值，不称陕西全量覆盖。

## 6. 验证与交付证据

每项 AT 分别记录代码与环境版本、授权范围、输入样本/来源、预期、实际、测试命令或浏览器步骤、执行人和原始证据路径。隔离/模拟、经授权真实站点、真实企业资料、浏览器、业务签认、目标环境部署**分别**记结论；未执行/阻塞不得写通过。真实来源的覆盖以“来源台账中的适用栏目与抽样窗口”计算；S1 记录按来源的抓取成功、空结果、失败、重试、最后成功时间、去重误合并/漏合并抽检；S3 另记文件实际取得率、条件漏提及待确认率，阈值待业务负责人签认后才用于发布判定。

执行者按 S0→S1→S2→S3 推进主链路，S4 在 S1 后按单站独立扩源；阶段/决定以 `annex-02-state-machine.md` 为准，准入类别以 `annex-03-qualification-types.md` 为准，首版四页以 `annex-04-pages.md` 为准。附件 AT-TEN-SM/QT/UI 分别落实到所标注的批次任务，不能只留文档不测。获准范围内独立任务可并行，但共享模型、权限、审计和现有 P1 文件须明确负责人避免冲突。每批先编写失败用例、再最小实现与回归；不为标签引入 LangGraph、第二套定时器或数据库。已有未提交改动不清理、不暂存、不提交、不推送，除非另获用户明确指令。每批完成时提交差距与测试结果、阻塞条件、剩余风险和下一批所需授权，不自动跨批次执行。正式业务批准与生产发布另行签认。
