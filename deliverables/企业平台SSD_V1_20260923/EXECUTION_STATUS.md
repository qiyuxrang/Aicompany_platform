## 0. 登记规则

1. 本文件**只记项目级**内容。任务级步骤、工作区字段、阻塞明细、证据清单一律写在对应任务的 `TASK_STATUS.md`，此处只放指针。
2. 只记已发生的事实。不写计划完成度、不写预测百分比。
3. 状态统一使用：`NOT_RUN` / `PASS` / `FAIL` / `BLOCKED` / `NOT_VERIFIED` / `NOT_APPLICABLE`。
   - `NOT_RUN`、`NOT_VERIFIED`、`BLOCKED` 均**不得**写成 `PASS`；`NOT_APPLICABLE` 须写明批准理由与范围。
   - mock / 模拟 / 夹具结果不得记 `PASS`。
   - **前端延期规则**：后端 / 核心范围通过但前端未接入时，另加范围标记 `CORE_PASS` / `FRONTEND_DEFERRED`；**不得**据此将 Browser E2E 或整个 P1 记为 `PASS`。前端延期不阻止无依赖的后端 Task 继续。详见 `docs/SPEC.md` 第 7 节。
4. **追加式**：新旧记录并存，不覆盖、不复写旧条目；旧条目有误时新增条目更正并说明原因。
5. 五类验收**分别登记、互不替代**：技术测试 / 真实依赖验证 / 浏览器验收 / 业务签认 / 部署验收。
6. 引用旧包历史时标注「历史引用，非本次重跑」，并说明证据是否仍适用。
7. 每个批次或 AT 登记须绑定：日期、规范版本、任务 ID、执行者、命令或浏览器步骤、证据位置、结论。
