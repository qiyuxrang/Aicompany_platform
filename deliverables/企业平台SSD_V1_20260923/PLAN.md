# 技术实施与交互设计

V0.2复用已交付基础，不建立第二套任务、审计或审批系统。历史实现与证据参见EXECUTION_STATUS.md；本文件中的新设计不能当作已实现接口。

## 架构与责任

React统一业务/管理入口→Django/DRF身份、对象权限、任务与批准→各业务能力。产品后台worker调用现有FastAPI模型网关、受控检索适配器和原文档工具；人事和经营复用原服务/库，工程按获批专业接入。

当前产品存在独立worker及持久任务/尝试/版本保护，不能称其已使用LangGraph。LangGraph是复杂流程的可选实现；只有明确差距与迁移收益时另行批准，不能为架构标签重写现有可靠执行链。首期允许同机分进程，不引入复杂微服务或n8n。

Django保存实际批准及业务状态。后台执行器只执行获批任务，模型不能自批。现有generate_for_use与模型路由复用，不新增公开万能推理API。RAGFlow只提供授权检索，原文档工具负责内容合同、母版及Office渲染，平台负责版本和最终审核。

## 工作区而不是聊天机器人

保留页面风格，在现有产品任务中组织资料准备、蓝图确认、生成进度、内容审阅、质量检查、成果审核、成果版本七个步骤；不要求七个独立页面。不完整数据标待确认，失败/无结果/待授权/处理中明确区分。

- 资料区：原文件/提取结果对照，显示来源定位、冲突和解决记录。
- 蓝图区：条件列表、章节范围与来源；条件变更必须解释受影响版本。
- 审阅区：显示可访问来源、问题位置、差异及影响预览；不能泄露无权访问的旧版本正文。
- 审核区：明确核验与批准不同；展示精确候选、检查结果和逐页渲染。
- 版本区：时间线、对比、下载，恢复创建新版本；本地重传不是实时Word编辑追踪。

对话作为未来可选入口，不能绕过相同接口、确认和权限。当前没有新增聊天实现任务。

## 逻辑数据关联

先映射现有模型/JSON/工件，以下是逻辑字段，不强制新增同名表。

| 对象 | 需要关联的最少信息 |
| --- | --- |
| 事实与来源 | 稳定ID、来源文件/片段/行、可获得的版本、事实/推断/冲突/缺项状态、确认记录 |
| 验收条件 | 稳定ID、原要求、适用内容、提出/确认者、检查方式、严重级别、规则版本、结果与证据 |
| 修改请求 | 输入/蓝图/章节版本、发起人和原因、明确/不确定影响、执行尝试、前后差异 |
| 审核与成果 | 候选哈希、源版本、检查证据、渲染记录、实际审核人、批准版本和撤权约束 |
| 留痕事件 | 服务端时间、操作者与发起者、AI任务/尝试、动作/对象/前后版本/结果、关联请求 |
| 回归运行 | 案例/期望/规则/模型配置/来源/模板版本、代码与环境、重复次数、分项结果和失败记录 |

事实、规则、模型配置及工件版本之间建立稳定关联，不靠标题猜测。可解释的是证据和操作链，不采集或展示模型隐藏推理过程。截图、模型自述和哈希不能替代人工批准。

## 可执行条件与变更

模型建议条件，用户确认后生效。程序检查确定性事实，模型辅助语义检查，授权人员决定业务可接受性。结果至少分为通过、失败、未知、未检查、待人工；未知不是通过。不生成虚假综合质量分。

条件、来源、规则或关键输入改变时，产生新版本并评估检查/批准失效。安全与权限规则不可被任务作者删除或降级；业务例外须授权、原因和精确版本，不改变历史失败结果。按原策略保守复核可先保留，只对已证明依赖一致的内容优化复用。

数量32改48仅为合成测试场景，不内置为真实业务数据。展示受影响章节/表格/已配置公式及检查；没有公式或可靠依赖时列待人工，不编造计算关系。尚无明确影响的内容进入扩大复核，不宣称全语义自动识别。

## 检索原生适配

原包已有内部portal-retrieval-v1合同和应用接线；直接填原生RAGFlow URL不保证兼容。确认实际版本后，将原生请求/响应映射到现有合同，优先复用已验证接口。直接HTTP API为无现成接入时的优先方案；已有独立可用MCP且满足合同则复用，只选一条链路，不同时自研两套。

服务端从任务/人员确定授权数据集与文档，不信任浏览器或模型扩大范围。适配分页、来源标识、版本可用性及错误分类，调用前后与阅读/发布时复验授权。来源位置无法取得时明示不可定位，不编造页码。权限校验失败后不得悄悄删去来源仍发布原成果；沿用已实现拒绝/新建任务策略，迁移另批。

资料冲突由人裁定，检索无结果、无权、超时、接口不兼容分开记录。授权和兼容性真实验证必须使用获准数据集正负样例，替身测试不充抵。

## 留痕与文件

关键业务写入和审计持久化应有可靠一致性；日志失败不能被当作完整留痕交付。正常业务/管理角色不能改删历史事件；存储管理员边界和删除保留期另有权限，不声称绝对不可篡改或司法存证。

差异内容、来源快照、旧版本和导出均按正文对象权限保护；摘要日志避免复制秘密和敏感正文。文件保存新路径并校验后再登记，批准版不可覆盖。外部上传记录上传人和父版本，可解析部分生成差异，无法可靠提取的格式/文本明确提示；不推断本地实际编辑人。

## 执行与状态复用

保留当前任务state/pending_action、租约/执行资格、幂等、事务保护和迟到写入拒绝，实施前读取实际枚举，不按设计稿重命名状态。人工批准与后续任务交接可靠持久化；等待人时释放执行资源。取消只有执行停止或失去写入权后才能报告完成。

渲染沿用原Office链路与冻结母版，验证目标服务身份、字体、安装、并发和清理。Linux与Windows兼容不能默认成立，必要时单独安排渲染worker，不能换渲染器掩盖格式退步。阶段失败可恢复，但不得自动恢复已失效批准。

## 接口与部署边界

优先扩展已有product API和错误合同，保持后端身份、版本冲突、幂等与撤权语义。不直接从浏览器调用模型/知识库，不向浏览器暴露秘密或本地文件路径。必要新路由先在对应任务中列出字段、版本和负向测试，不写出一个与现有代码竞争的第二套接口。

各旧项目代码改动须单独批准范围，不stash/reset用户成果。隔离数据库、合成/获准样例优先；本次规范修订不启动服务、迁移数据或部署。正式发布需当前范围的备份恢复、业务验收和运行条件，不借用不覆盖新增数据的历史演练。
