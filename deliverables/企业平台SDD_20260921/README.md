# 企业平台 SDD 规范包

版本：0.1｜编制日期：2026-09-21｜状态：待业务与技术负责人批准。

本包将《企业平台总体规划.docx》改造为规范驱动开发材料。SDD指Spec-Driven Development，不再把SSD架构说明当作可直接实施的完整规范。原文保留不动；本包不代表业务代码已修改、功能已实现或测试已通过。

## 阅读与执行顺序

1. `REVIEW.md`：原文评估、缺口和改造结论。
2. `specs/00-overview.md`：总体范围、分期、数据归属、待确认事项。
3. `specs/01-platform.md`至`specs/05-business.md`：只读本次相关模块，不把所有模块一次交给AI开发。
4. `PLAN.md`：技术边界、状态和接口约束。
5. `TASKS.md`：选择一个任务包，检查前置条件后实施。
6. `ACCEPTANCE.md`：登记实际证据；未运行的验收一律保持未执行。
7. `AI_HANDOFF.md`：直接交给编码代理的执行指令。

人读Word总册；AI开发以本包Markdown的获批版本为准。Word是同源快照，不允许只改Word而不更新规范源。需求变化先修改相关spec、任务和验收项，再重新生成Word。

## 当前授权边界

- 可自主开展：只读盘点、接口梳理、脱敏样例整理、测试设计和规范评审。
- 实施前必须批准：本次模块范围、适用决策项及允许修改的仓库和文件。
- 不得默认执行：正式库写入、旧系统上线、外发公司或人事资料、购买服务、破坏性迁移、合库和全机配置修改。
- 工程成本目前只有范围草案；定额数据与业务口径未确认前不得进入正式计价实现。

## 文件说明

`企业平台总体规划_SDD评审版.docx`包含评估、需求、技术计划、任务和验收规则。`specs/`及其他Markdown是可交给AI的规范源。`qa/`仅为文档生成和检查证据，不是业务测试结果。

本包未安装Spec Kit。采用“规范→澄清→技术计划→任务→实施→证据验收”的工作方式，不绑定工具命令。
