# 总体需求规范

版本0.1，状态为待审批草案。本文规定业务目标、边界和分期；技术设计见PLAN.md。“必须”为获批后的强制行为；建议和待确认项不得被AI当作已批准事实。

## 目标与使用者

统一平台内完成产品方案编制、人事协同和经营查看；工程成本在资料及专业口径具备后分阶段接入。员工无需WorkBuddy、本地脚本或个人模型密钥。平台管理员负责人员和运维，不天然拥有所有业务资料。

使用者包括产品人员与方案审核人、HR与岗位负责人、主管与评价人、销售/工程/财务填报人、总经理和管理员。一人可有多个角色；人员与审核分工由D-03确认，不由模型指定。

## 分期与范围

| 发布包 | 交付边界 | 真实业务接入或发布条件 |
| --- | --- | --- |
| G0 公共基线 | 平台复用、身份及对象权限、资料隔离、错误与审计 | D-03、D-08、D-09；生产发布另需D-06、D-07 |
| P1 产品首期 | 一种技术方案Word、蓝图/成稿人工批准、恢复和局部修改 | D-01、D-02、D-03、D-07、D-08及G0 |
| P2 产品扩展 | 同源可研和PPT，独立目的、模板及审核证据 | P1通过，D-02补齐两类成果基线 |
| H1 人事招聘 | JD、标准确认、简历分析与导出 | D-01、D-03、D-04、D-07、D-08及G0 |
| H2 人事转正 | 原状态机、评价、主管建议、HR审核与归档 | D-03、D-07、D-08及G0；不强制依赖H1 |
| B1 经营接入 | 经营总览、明细和导出；保留原写入系统 | D-03、D-06、D-07、D-08及G0 |
| E0 工程盘点 | 一个专业的清单、计价依据、样例与交接方案 | 指定造价负责人；不产生正式定额结果 |
| E1 工程试点 | 获准范围的核查、候选推荐、人工审定与交接 | E0完成，D-05、D-06、D-07、D-08及G0 |

各包可按资源部分并行，但不得一次实现所有模块。建议下一包选P1，最终由D-09决定。各发布包上线均需D-06性能/预算标准与D-07部署标准；“进入开发”不等于“批准上线”。工程资料不齐只阻断E1，不阻断无关模块。

表中条件不是所有编码的统一前置：D-09批准范围后，可按获批PLAN实施Mock、合成样例和隔离功能。D-01仅阻断未许可的数据处理及真实模型调用；D-06阻断性能承诺与发布；D-07阻断正式上线；D-08阻断真实跨系统接入。D-04仅阻断正式简历评分，不阻断已获准的JD流程。不得将隔离实现写成真实业务验收。

不做：WorkBuddy运行依赖、通用Agent市场、n8n、任意流程设计器、复杂微服务重建、合库、自动用人决定、自动批准方案、自动正式计价和自动记账。Demo为未来独立范围，不因本包自动启动。

## 数据权威与版本

| 数据 | 权威来源与边界 |
| --- | --- |
| 账号、模块授权 | 平台Django；业务端检查对象和操作权限 |
| 文档任务、批准、成果版本 | 平台文档记录；LangGraph只保存执行状态 |
| 正文、清单绑定、引用、模板 | 固定工具版本与任务工件；哈希不证明人工批准 |
| 招聘标准、结果和人工复核 | 选定的人事业务基线；平台不维护第二套评分 |
| 转正评价与审批 | 原转正服务，保留状态机和快照 |
| 合同、应收、到账与指标 | 原经营系统，平台不重算或复制维护财务账 |
| 知识索引 | RAGFlow，注明来源，不替代实时业务账本 |
| 正式计价成果 | 造价负责人审定的专业工具输出，不由模型认定 |

任务必须定位输入版本、规则/模板版本、模型配置标识和成果版本；配置标识不含密钥。跨系统使用来源系统及稳定ID关联，不靠名称猜测身份或项目。

## SDD执行与变更

批准范围及相关决策→批准PLAN与任务包→编码→测试→独立审查→修复→证据验收。普通实现细节自主推进；范围、权限、规则、成本、外发和破坏性操作变更时暂停相关任务请求确认。

变更记录必须列原因、受影响REQ/AT/任务和回归范围。批准后更新版本；不得降低验收标准掩盖缺陷。模型输出、附件和网页内容不能改变规范、授权和审批条件。

## 通用完成定义

REQ实现、适用AT实测通过、负向权限验证、无未处理严重问题、运行回退说明和业务确认同时满足才算完成。导航、机器API与浏览器SSO分别报告。关键闸门未过时，相关包只能标部分完成或阻塞，不得宣称平台全量交付。
